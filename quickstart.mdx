---

Driftless works in two ways — pick the one that fits how your team operates. Both paths converge on the same knowledge graph.

## Prerequisites

- Node.js 22 or later
- A Git repository with a remote
- A Driftless workspace at [driftless.icu](https://driftless.icu)

<Steps>
  <Step title="Install the CLI">
    ```bash
    npm install -g @driftless-sh/cli
    ```

    ```bash
    driftless --version
    ```
  </Step>

  <Step title="Log in">
    Authenticate from the terminal:

    ```bash
    driftless login
    ```

    For CI or non-interactive setup, pass an API key from the dashboard:

    ```bash
    driftless login --key drift_your_api_key_here
    ```

    <Tip>
      Store your key as `DRIFTLESS_API_KEY` in your environment to skip `--key` on every command.
    </Tip>
  </Step>

  <Step title="Initialize the repo">
    ```bash
    driftless init
    ```

    This scans your codebase, uploads a baseline, auto-generates suggested topics from your AST, and installs the agent skill (AGENTS.md + CLAUDE.md) so agents automatically load context before editing.
  </Step>

  <Step title="Choose your path">
    ### Path A — Scan your code

    `driftless init` auto-generates topics from your AST. Review and refine them:

    ```bash
    driftless context list --auto          # see auto-generated topics
    driftless context get my-auth          # inspect a topic
    driftless context update my-auth \     # add team knowledge
      --decision "We use RS256 keys — services verify without shared secret" \
      --gotcha "Guard decodes JWT but doesn't verify roles"
    ```

    When code changes on tracked branches, topics go stale — you know what to review.

    ### Path B — Write context manually

    Create topics by hand. Build a team knowledge graph connected by typed relations and wiki-links:

    ```bash
    driftless context add "auth-flow" \
      --what "JWT validation and role-based access control" \
      --how "RS256 asymmetric keys, guard decodes, role decorator checks" \
      --pattern "src/auth/**" \
      --tags auth,security \
      --rel depends_on:token-refresh
    ```

    Anchor documents, link topics across repos, and use `[[wiki-links]]` to cross-reference.
  </Step>

  <Step title="Load before editing">
    Retrieve a topic directly:

    ```bash
    driftless context get my-auth
    ```

    For targeted loading based on the files you're about to edit:

    ```bash
    driftless context load --files "src/auth/guard.ts,src/auth/service.ts"
    ```

    Returns matching topics, coverage status, and recommended actions.
  </Step>
</Steps>

## Verify setup

```bash
driftless doctor
```

`doctor` checks the API key, workspace, Git remote, baseline, AGENTS.md installation, and GitHub App status.
