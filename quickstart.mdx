<Steps>
  <Step>
    **Install the CLI**

    ```bash
    npm install -g @driftless-sh/cli
    ```

    Verify installation:

    ```bash
    driftless --version
    ```
  </Step>
  <Step>
    **Log in**

    Get your API key from the [dashboard](https://driftless.icu) and authenticate:

    ```bash
    driftless login --key drift_your_api_key_here
    ```

    <Tip>
      Store your key as `DRIFTLESS_API_KEY` in your environment to skip `--key` on every command.
    </Tip>
  </Step>
  <Step>
    **Initialize your repo**

    Run init from the root of your repository. This scans your codebase, uploads a baseline to Driftless Cloud, and installs the agent skill.

    ```bash
    driftless init
    ```

    <Tip>
      For monorepos, scope the scan to a subdirectory:

      ```bash
      driftless init --src apps/api
      ```
    </Tip>

    Init creates `.driftless/config.yml` and `.driftless/skill.md` in your repo. The skill file is what agents read to learn the Driftless workflow.
  </Step>
  <Step>
    **Create your first context topic**

    Anchor a topic to your auth code so agents and teammates know how it works:

    ```bash
    driftless context add "my-auth" \
      --what "Handles JWT validation and role-based access control" \
      --pattern "src/auth/**" \
      --tags auth,security \
      --kind code-context
    ```

    You can also add decisions and gotchas:

    ```bash
    driftless context update my-auth \
      --decision "We use asymmetric RS256 keys, not HS256" \
      --gotcha "The guard decodes the JWT but doesn't verify roles — that happens in the role decorator"
    ```
  </Step>
  <Step>
    **Load context before coding**

    Any agent or teammate can now retrieve this context before touching auth files:

    ```bash
    driftless context get my-auth
    ```

    For targeted loading based on the files you're about to edit:

    ```bash
    driftless context load --files "src/auth/guard.ts,src/auth/service.ts"
    ```
  </Step>
</Steps>
