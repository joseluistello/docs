title: 'Self-hosted agents (OpenClaw & Hermes)'
description: "Connect OpenClaw or Hermes to Brein through the compatibility CLI, the engineering skill, or the remote MCP endpoint."
---

OpenClaw and Hermes Agent are self-hosted agents that may have shell access, skills, and MCP support. Brein offers two separate doors:

- **CLI + engineering skill** for a repository-based engineering workflow: read relevant Cerebro context before editing and write back one clean document after learning something durable.
- **Remote MCP** for an AI client that should work with Brein's governed commercial capabilities.

The CLI and package names remain `driftless` compatibility contracts. The public MCP endpoint uses neutral capability names.

## Shared connection facts

| | Value |
|---|---|
| MCP endpoint | `https://api.trybrein.com/mcp` |
| MCP authentication | `X-API-Key: drift_…` or OAuth for supported clients |
| CLI package | `@driftless-sh/cli` |
| API key | Brein dashboard → **Settings → API Keys** |

A key is scoped to the workspaces it is authorized for. It does not become a super key. Remove a person's membership and access to that workspace is revoked through the normal authorization boundary.

## CLI + skill

Install and authenticate on the host that executes the agent:

```bash
pnpm add -g @driftless-sh/cli
# or
npm install -g @driftless-sh/cli
driftless login --key drift_your_api_key_here
```

From the repository or workspace root:

```bash
driftless install-skill
```

The skill teaches the engineering context loop. It does not grant the agent permission to send email, reveal contacts, spend credits, or make a consequential CRM decision without the underlying server authorization.

## Remote MCP

For OpenClaw:

```bash
openclaw mcp add driftless \
  --url https://api.trybrein.com/mcp \
  --transport streamable-http \
  --header X-API-Key:drift_your_api_key_here
```

For Hermes, add the endpoint under `mcp_servers` in `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  driftless:
    url: "https://api.trybrein.com/mcp"
    headers:
      X-API-Key: "drift_your_api_key_here"
    tools:
      resources: false
      prompts: false
```

Use the current neutral tool names, such as `context_retrieve`, `context_get`, `collection_query`, `crm_record`, `people_search`, and `sequence_activate`. Do not build a new integration around retired tools such as `driftless_context_search`, `driftless_collection`, `driftless_tags`, or `driftless_areas`.

## Verify the connection

1. Run a bounded read such as `context_retrieve` or `collection_query`.
2. Confirm the response belongs to the intended workspace.
3. If a write is required, use the current tool contract and the explicit authorization its result describes.
4. Reconnect or reload MCP after a schema change; clients cache tool definitions per session.

A `401` means the API key or OAuth token did not reach Brein. A `403` means the caller is authenticated but lacks the required workspace or role authority.
