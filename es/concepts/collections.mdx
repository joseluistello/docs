Una **Collection** es una tabla configurada del workspace. Un **Record** es una fila tipada. En el producto actual de Brein, el uso customer-facing es Prospectos: una Collection de personas que el workspace adquiere y archiva explícitamente.

Una empresa, observación de proveedor, licitación, adjudicación, permiso, marca de riesgo o fila de research no es un Record del CRM. Esos objetos pueden permanecer como contexto de mercado o evidencia. Una persona se convierte en Record sólo por el camino de contacto revelado/importado.

## Qué contiene una Collection de Prospectos

- **Campos de contacto:** persona, cuenta, rol, disponibilidad de canal y campos acotados de ventas.
- **Ciclo de vida:** etapas como nueva, contactada, respondió, reunión, cerrada o descartada, configuradas para el proceso comercial del equipo.
- **Criterio de Cerebro:** documentos que explican cómo debe trabajar el equipo estos contactos.
- **Lecturas acotadas:** páginas active-only por defecto, con continuación cuando hay más Records.

El modelo Collection/Record subyacente es infraestructura compartida. No significa que Brein sea un constructor genérico de bases de datos para bug trackers, calendarios o schemas arbitrarios.

## Ciclo centrado en contactos

```text
persona candidata enmascarada
  → cotización y confirmación explícitas
  → contacto revelado/importado
  → people_file explícito
  → Record del CRM
  → estado, historial y seguimiento
```

`crm_record` actualiza un Record de contacto existente. No crea uno desde una empresa o una fila de evidencia. `collection_query` lee; `crm_collection` crea un contenedor vacío; `people_file` archiva la persona adquirida.

## Contrato MCP

La superficie MCP actual es:

- `collection_query` — lecturas acotadas de lista, query, get y aggregate;
- `crm_record` — actualiza un Record de contacto existente, consulta historial o programa seguimiento;
- `crm_collection` — crea una Collection vacía orientada a contactos;
- `people_file` — crea el Record desde una persona revelada/importada.

El CRUD genérico de Collection, `entity`, purge permanente y borrado de Record no son tools MCP públicas. El nombre anterior `collection_record` es un alias oculto para lecturas y actualización de Records existentes; no restaura el comportamiento antiguo de crear cuentas de empresa.

## CLI y REST

CLI y REST todavía exponen operaciones de configuración y lifecycle de bajo nivel para administradores y clientes técnicos. Lee el contrato actual antes de usarlas; no infieras un workflow de cliente por la existencia de una ruta Record genérica.

## Entities

Puede existir un modelo de identidad compartida dentro de la plataforma, pero la tool pública de entities no es parte del producto comercial. Una persona, empresa u observación externa se vincula al trabajo CRM sólo cuando el servidor puede atestiguar la relación; los nombres aproximados y URLs del cliente no prueban identidad.
