Brein es un workspace de inteligencia comercial. Mantiene conectados el criterio comercial, la evidencia publicada y el trabajo que sigue en un loop gobernado:

> **Señal → Contexto → Evidencia → Inferencia → Acción → Decisión humana → Resultado → Aprendizaje**

El objetivo no es convertir cada pregunta en un workflow de agente. El objetivo es que la siguiente decisión comercial sea más explicable que la anterior.

## Las partes del loop

### Contexto: Cerebro

Cerebro contiene la verdad comercial durable que un equipo quiere reutilizar: oferta, cliente ideal, exclusiones, geografía, señales de compra, compradores, mensajes, playbooks y decisiones aprendidas.

Son documentos markdown dentro de carpetas. Un documento nace compartido con el workspace; no hay una escalera de aprobación que subir. Reescribir un documento es la forma normal de consolidar conocimiento durable. El contexto de ingeniería y las anclas de rutas siguen soportados cuando describen un sistema real, pero no son el centro del producto.

### Evidencia: inteligencia de mercado acotada

Brein busca en corpora de mercado gobernados empresas publicadas, licitaciones, adjudicaciones, permisos, registros y evidencia relacionada. Cada carril conserva su propio significado, filtros, reglas de identidad y procedencia.

- Un resultado es un candidato, no un mercado completo.
- Un resultado vacío no prueba que algo no exista.
- Una adjudicación es una adjudicación publicada, no un pago.
- Un permiso es un permiso registrado, no una garantía operativa actual.
- Una identidad aproximada sigue siendo aproximada salvo que el servidor pueda atestiguar una relación más fuerte.

### Inferencia: la razón para revisar

El sistema puede proponer relevancia, compradores probables o señales de compra. Son inferencias que una persona debe revisar. Un puntaje ordena la atención; no afirma que una compra sea probable ni que un evento ya haya ocurrido.

### Acción: un siguiente paso acotado

El siguiente paso debe corresponder al objeto que la persona está trabajando:

- inspeccionar una empresa y sus personas;
- cotizar y autorizar explícitamente un grupo seleccionado;
- archivar un contacto revelado o importado en Prospectos;
- preparar y revisar una campaña;
- ejecutar un brief de investigación y devolver un dossier.

Brein no crea un Record del CRM a partir de una empresa, proveedor, licitación, adjudicación, permiso o evidencia. La persona es la unidad que puede entrar al flujo CRM.

### Resultado: una decisión humana

La persona decide qué merece atención, qué revelar, qué activar y qué descartar. Brein conserva la decisión, la evidencia usada y el siguiente paso para que el resultado pueda revisarse después.

## Cómo encajan las superficies

- **Empresas** busca en un directorio acotado.
- **Personas** muestra decisores públicos enmascarados dentro de una empresa.
- **Contactos** es la libreta adquirida: personas reveladas o importadas.
- **Licitaciones, Proveedores, Adjudicaciones y Registros** exponen su propia semántica.
- **Investigador** produce dossiers de investigación durable con compuertas de verificación.
- **Cerebro** conserva el criterio que debe guiar el trabajo.
- **Prospectos** opera Records de personas que el equipo archivó explícitamente.
- **Campañas** prepara y gobierna secuencias. Crear un borrador es inerte; enviar exige autorización humana separada sobre la audiencia y el contenido revisados.
- **Configuración** administra workspace, equipo, facturación, conexiones, privacidad y eliminación.

## Las puertas del cliente y del developer

El dashboard es la superficie principal del cliente. La [CLI](/es/cli/setup), [MCP](/es/mcp/overview) y [API REST](/es/api/overview) son puertas sobre las mismas capacidades gobernadas, no productos separados.

El comando `driftless`, el namespace del paquete, el prefijo de API key y los aliases ocultos son nombres de compatibilidad durante la migración. Las tools MCP públicas usan nombres neutrales.

## El contexto de ingeniería sigue soportado

Cuando Brein se usa dentro de un equipo de software, el mismo modelo de Cerebro puede guardar decisiones, gotchas, invariantes y anclas de rutas. El loop de ingeniería es simple:

1. lee el contexto relevante antes de editar;
2. haz el cambio coherente más pequeño;
3. escribe un documento limpio cuando aprendas algo durable;
4. usa anclas de rutas para notar cuándo una afirmación puede estar vieja.

Es un uso soportado de Brein, no el centro del producto comercial.

## Lo que Brein no es

- No es un constructor genérico de bases de datos ni un exportador exhaustivo de directorios.
- No es un gestor de proyectos, revisor de PR, sistema de CI o consola de observabilidad de agentes.
- No convierte cada inferencia del modelo en verdad.
- No lee la bandeja de entrada del cliente ni compra, revela, archiva o envía algo silenciosamente.
- No promete decisiones autónomas. Las escrituras importantes y el envío permanecen atribuibles y autorizados por una persona.
