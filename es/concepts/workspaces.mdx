Un workspace es el contenedor principal del trabajo comercial de Brein, Cerebro y las conexiones. Una persona puede pertenecer a varios workspaces y cambiar entre ellos sin crear una super credencial.

## Qué pertenece a un workspace

- documentos de Cerebro y su visibilidad;
- Collections y Records de contactos de Prospectos;
- Empresas, Contactos adquiridos, Listas, evidencia de mercado, Research y Campañas;
- miembros, roles, facturación y uso comercial;
- integraciones y credenciales API con scope.

Cada recurso del cliente está acotado al workspace. Un caller autorizado para un workspace no puede usar esa credencial para leer datos de otro.

## Identidad y membresía

Clerk autentica a la persona. La membresía de un workspace es un hecho de autorización separado. Una persona no es miembro salvo que exista una fila viva; un no-miembro recibe el mismo comportamiento not-found que un recurso no disponible.

| Rol | Puede |
|---|---|
| `owner` | Administrar workspace, miembros, roles, facturación, credenciales y eliminación. |
| `admin` | Administrarmembers y configuración ordinaria dentro de los límites del owner. |
| `member` | Leer y trabajar las superficies comerciales y documentos compartidos de Cerebro dentro del workspace. |

La comprobación exacta vive en el guard de la API y en el servicio dueño de la acción. Un rol nunca mejora una credencial entre workspaces.

## Credenciales con scope

Una API key se emite para uno o más workspaces autorizados. `driftless login` registra los workspaces que puede alcanzar la key y `workspace switch` cambia el objetivo local.

- Eliminar la membresía de una persona revoca su acceso vivo.
- Una key no obtiene un rol superior al de su identidad humana autorizada.
- Los tokens OAuth MCP pueden llevar grants adicionales después del consentimiento explícito.
- Crear y revocar keys ocurre en el dashboard autenticado o mediante la API del workspace.

## Workspaces en distintas superficies

| Superficie | Autenticación | Workspace activo |
|---|---|---|
| Dashboard | Sesión Clerk | El slug del workspace en la URL. |
| CLI | API key con scope | El registro local y el objetivo activo. |
| MCP | API key o token OAuth | El workspace autorizado por el token o el target soportado explícitamente. |

El namespace `driftless` sigue siendo un contrato de compatibilidad para la CLI, paquete, prefijo de API key y aliases ocultos. No es un segundo producto ni un segundo modelo de workspace.
