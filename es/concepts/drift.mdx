---
title: 'Drift y frescura'
description: 'Cómo Brein marca un documento cuyas rutas de ingeniería pueden haber cambiado.'
---

El drift es una señal de contexto de ingeniería, no una señal del mercado comercial. Ayuda a un equipo de software a notar cuándo las rutas ancladas de un documento ya no respaldan la afirmación que contiene.

## Inspección local

Desde un checkout:

```bash
driftless context get --diff
driftless context get --diff --mark
```

El primer comando muestra los documentos coincidentes sin cambiar el estado del workspace. `--mark` es explícito y registra la señal de drift para los documentos coincidentes. Una coincidencia dice "revisa de nuevo", no "el documento es falso".

## Qué hacer después

1. Lee el código o configuración que cambió.
2. Lee el documento anclado y decide si cambió la afirmación durable.
3. Si todavía se sostiene, reescribe o actualiza el documento.
4. Si el anchor ya no es relevante, quítalo o acótalo.
5. Si el documento ya no forma parte del trabajo actual del workspace, archívalo mediante el lifecycle humano.

El modelo actual de documentos no tiene un `status: reviewed` que vuelva autoritativo un documento. La frescura viene del documento actual y de su relación con el anchor, no de un badge de gobernanza retirado.

## Diagnósticos opcionales

```bash
driftless context doctor
driftless sync
```

`context doctor` audita la capa técnica de documentos. `sync` sigue siendo un digest de compatibilidad para workflows antiguos de repositorio; no es un briefing de cliente ni una automatización comercial. La inteligencia comercial de Brein tiene su propia semántica de evidencia y frescura.

## Seguridad

El drift es un nudge, no una alarma. Tolera falsos positivos para que una persona tome la decisión final. Nunca significa que un agente deba reescribir un documento automáticamente, enviar un mensaje o crear un Record CRM.
