---
title: 'Agentes self-hosted (OpenClaw y Hermes)'
description: "Conecta OpenClaw o Hermes al servidor MCP alojado de Brein."
---

OpenClaw y Hermes pueden usar Brein mediante el mismo servidor MCP remoto que cualquier otro cliente de IA:

```text
https://api.trybrein.com/mcp
```

El cliente elige el modelo. Brein aporta los datos y las acciones del workspace, incluyendo Empresas, Personas, Prospectos, Campañas, Cerebro e Investigador.

## Usa OAuth cuando esté disponible

Prefiere el flujo OAuth normal del cliente. Selecciona el workspace de Brein que quieres que use el agente, revisa los permisos solicitados y termina la autorización en el navegador.

## Usa una API key cuando el cliente requiere headers

Crea una key con scope en **Configuración → API Keys** y consérvala en el almacén de secretos o variables de entorno del cliente.

Para OpenClaw, la conexión tiene esta forma:

```bash
openclaw mcp add brein \
  --url https://api.trybrein.com/mcp \
  --transport streamable-http \
  --header "X-API-Key: ${BREIN_API_KEY}"
```

Para Hermes, agrega el servidor bajo `mcp_servers`:

```yaml
mcp_servers:
  brein:
    url: "https://api.trybrein.com/mcp"
    headers:
      X-API-Key: "${BREIN_API_KEY}"
    tools:
      resources: false
      prompts: false
```

La expansión exacta de la variable depende del cliente. Nunca guardes la key cruda en un repositorio compartido.

## Verifica la conexión

1. Lista los workspaces a los que puede acceder la credencial.
2. Ejecuta una lectura pequeña, como una búsqueda de mercado o una consulta CRM acotada.
3. Confirma que el resultado pertenece al workspace previsto.
4. Reconecta el cliente después de un cambio de tools si el cliente cachea su lista.

Un `401` significa que la credencial no llegó a Brein. Un `403` significa que la credencial es válida, pero no tiene acceso al workspace o a la acción solicitada.
