El Broker es el plano de ejecución sobre una Connection que ya existe. Lee datos conectados y ejecuta operaciones nombradas del proveedor dentro del workspace, con autorización, rollout, grants y auditoría.

El Broker no conecta providers. Empieza por [integraciones y conexiones](/es/integrations/overview) y usa el Broker mediante:

- la CLI (`driftless broker ...`);
- REST bajo `/api/v1/workspaces/:slug/broker`;
- tools MCP sintetizadas como `<provider>_records` y `<provider>_document_content`, cuando el provider está listo y el rollout del workspace lo permite.

No existe un router MCP genérico `driftless_broker`. Una llamada legacy con ese nombre no es una capability pública. Las tools MCP sintetizadas son específicas del provider y de sólo lectura; no exponen una acción genérica, escrituras ni setup de conexiones.

## Qué puede hacer

La superficie CLI y REST puede inspeccionar operaciones disponibles, ejecutar una operación nombrada de lectura o escritura, leer registros sincronizados y materializar contenido soportado. El conjunto exacto lo define el provider conectado y la política de rollout del workspace. Un agente no debe inventar una operación que el provider no lista.

| Capacidad | CLI | REST | MCP |
|---|---|---|---|
| Inspeccionar conexiones y operaciones | `broker connections`, `broker operations` | rutas de conexiones y operaciones | Sin router genérico |
| Ejecutar una operación nombrada | `broker invoke <provider> <operation>` | ruta invoke del Broker | Sin tool de acción genérica |
| Leer registros sincronizados | `broker records` | ruta records del Broker | `<provider>_records` cuando se sintetiza |
| Leer contenido live de documentos | `broker page` | ruta page-content del Broker | `<provider>_document_content` cuando se sintetiza |
| Conectar o desconectar un provider | `integration connect` / `integration` | rutas de setup de integración | Sólo humano/CLI |

## Gates y seguridad

El Broker falla cerrado cuando la feature está deshabilitada, el rollout externo está cerrado, la operación no está permitida por política o el caller no tiene grant. Una capability listada no significa usable. Una escritura nunca hereda autorización de una búsqueda de mercado, una lectura CRM o un borrador de secuencia.

Cada operación ejecutada está acotada al workspace y es auditada. Las escrituras requieren la idempotency key soportada por el provider; Brein no inventa garantías que el provider no ofrece. Un write fallido no debe reintentarse ciegamente con otra key.

## Materialización es una operación separada

Leer un provider, leer registros sincronizados y materializar contenido son operaciones diferentes:

- una lectura live pide datos acotados al provider;
- una lectura de registros sincronizados usa el mirror conectado;
- materializar crea un objeto propio de Brein sólo cuando la operación nombrada lo soporta explícitamente;
- recuperar contexto nunca consulta silenciosamente a un provider.

Una observación externa no se convierte en contacto CRM ni en verdad comercial sólo porque el Broker la leyó. Una persona debe ser revelada o importada explícitamente antes de entrar al flujo de contactos.
