Brein mantiene los datos del cliente asociados al workspace y al rol autorizado para usarlos.

## Credenciales

Brein guarda API keys, tokens OAuth, credenciales de providers y secretos de webhooks detrás de su frontera de cifrado. Una API key cruda se muestra sólo cuando se crea.

Una key puede limitarse a workspaces y roles concretos. No es una key universal. Cuando una persona sale de un workspace, su acceso activo se elimina mediante las reglas normales de membresía.

## Autenticación

- **OAuth 2.0 con PKCE** — lo usan clientes MCP publicados como ChatGPT y Claude.
- **API key** — la usan integraciones soportadas y clientes self-hosted.
- **Sesión autenticada del dashboard** — se usa para acciones dentro del producto Brein.

Cada solicitud al workspace está autenticada y limitada a ese workspace. Una credencial autorizada en un workspace no puede leer los datos de otro.

## Qué puede hacer un cliente de IA

El servidor MCP expone las capacidades comerciales del workspace autorizado. No le da al modelo acceso sin restricciones a la base de datos.

Los límites importantes siguen existiendo:

- los datos de contacto permanecen ocultos hasta que la persona elige una búsqueda;
- la búsqueda de contactos, las escrituras CRM y la activación de campañas tienen sus propias revisiones y confirmaciones;
- los resultados de mercado e investigación muestran qué se encontró y qué sigue incierto;
- una campaña preparada no se envía sola;
- Brein no lee el inbox del cliente ni expone credenciales almacenadas.

## Email saliente

Un sender conectado no es permiso para enviar. Brein revisa la audiencia, el contenido, los derechos y el estado del sender antes de activar. Una campaña requiere una confirmación humana separada.

Brein puede observar la interacción con mensajes que envió, como una apertura, un clic o la existencia de una respuesta. No importa el contenido del inbox del cliente.

## Reportar un problema de seguridad

Reporta una posible vulnerabilidad de forma privada a [security@driftless.icu](mailto:security@driftless.icu). No incluyas credenciales, datos de clientes ni contenidos de mensajes en un issue público.
