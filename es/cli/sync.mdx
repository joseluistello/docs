---
title: 'Sync y ramas'
description: "Un resumen opcional, para todo el equipo, de lo que drifteó alrededor de tus topics."
---

`driftless sync` es un resumen **opcional** para todo el equipo. Casi nunca lo necesitas, y nunca para empezar. El drift ya te llega como un badge de frescura cuando haces `driftless context get` sobre el área en la que trabajas. Recurre a `sync` solo cuando quieras revisar de una vez todo lo que se movió.

No inspecciona tu diff local y no recupera contexto específico de archivos. Trae el estado de memoria del repo desde Driftless Cloud y responde una sola pregunta:

> ¿Qué cambió alrededor de los topics de este repo desde la última vez que miré?

## Comando

| Comando | Flags | Descripción | Ejemplo |
|---|---|---|---|
| `sync` | `--json` | Muestra topics stale, actividad reciente de PR y ramas rastreadas | `driftless sync` |

```bash
driftless sync
```

Salida típica:

```text
▌ acme/platform
  workspace: acme  (resolved via config)
  tracking:  main, staging

⚠  2 topics drifted, the team changed code these topics cover, context may be behind:
   auth-boundaries
     src/auth/session.ts changed
     → review the change; if it changed how this works: driftless context update auth-boundaries --what "..." --how "..."
```

## Qué revisa sync

| Señal | Fuente | Qué hacer |
|---|---|---|
| **Topics stale** | Eventos de push de GitHub en ramas rastreadas | Revisa el código que cambió y actualiza el topic si cambió el comportamiento |
| **Actividad reciente de PR** | Observaciones de la GitHub App | Lee los topics tocados antes de trabajar en la misma área |
| **Ramas rastreadas** | Configuración del repo en Driftless Cloud | Usa `driftless branches` para ver o cambiar el alcance del drift |

## Cuándo usar sync

El loop de cada día no necesita `sync`. Ve directo a la recuperación, que lleva el badge de frescura incorporado:

```bash
driftless context get --files "src/auth/session.ts,src/auth/token.ts"
```

Recurre a `sync` solo cuando quieras la foto completa de todo el equipo de una sola vez:

```bash
driftless sync
```

Si ya tienes cambios locales y quieres los topics que coinciden con el diff:

```bash
driftless context get --diff
```

## Salida JSON

Usa `--json` cuando un agente o un script necesite salida estructurada:

```bash
driftless sync --json
```

La salida JSON incluye:

| Campo | Significado |
|---|---|
| `repo` | org/repo de GitHub resuelto desde el remote actual |
| `workspace` | Slug del workspace de Driftless |
| `tracking` | Rama por defecto y ramas rastreadas adicionales |
| `stale_topics` | Topics cuyo código anclado cambió |
| `pr_activity` | Observaciones recientes de PR y topics tocados |

## Ramas

El estado stale está acotado a las ramas rastreadas. Si un push ocurre en una rama no rastreada, Driftless registra la actividad pero no marca topics como stale desde esa rama.

| Comando | Flags | Descripción | Ejemplo |
|---|---|---|---|
| `branches` | `--json` | Ver las ramas rastreadas | `driftless branches` |
| `branches add` | `<branch>` | Rastrea una rama | `driftless branches add staging` |
| `branches rm` | `<branch>` | Deja de rastrear una rama | `driftless branches rm staging` |
