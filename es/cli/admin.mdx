Estas familias administran el workspace en sí. Varias son solo owner/admin, aplicado del lado del servidor. Agrega `--json` a cualquier comando para salida de máquina. Para login, `doctor`, `install-skill` y `sync`, ver [CLI Setup](/es/cli/setup); para cambiar de workspace, ver [Comandos de context](/es/cli/context).

## Members

| Comando | Descripción |
|---|---|
| `member list` | Lista members (id, rol, email). |
| `member invite <email> [--role admin\|member]` | Invita un member. `owner` no se puede invitar. |
| `member role <memberId> <role>` | Setea el rol de un member: `owner`, `admin` o `member`. |
| `member rm <memberId>` | Quita un member. |
| `member invites` | Invitaciones pendientes. |

Las escrituras de member son acciones owner/admin. Los roles son `owner`, `admin`, `member`; las invitaciones solo pueden conceder `admin` o `member`.

```bash
driftless member invite dev@acme.com --role member
driftless member role mem_123 admin
```

## Areas y tags

| Comando | Descripción |
|---|---|
| `area list` | Lista areas (los dominios bajo los que se archivan los topics). |
| `area add <name> [--description "..."]` | Crea un area. |
| `area rename <id> <new-name>` | Renombra un area (owner/admin). |
| `area rm <id>` | Elimina un area; sus topics quedan sin archivar (owner/admin). |

Los tags se cubren en [Comandos de context](/es/cli/context): `tags`, `tags add`, `tags rename`, `tags rm`. Renombrar y borrar un area o un tag son actos de curación owner/admin.

## Repositorios

| Comando | Descripción |
|---|---|
| `repo list` | Repositorios enlazados. |
| `repo link <org/repo>` | Enlaza un repositorio de GitHub (debe tener forma `org/repo`). |
| `repo unlink <id>` | Desenlaza un repositorio. |

```bash
driftless repo link acme/api
```

## Notas

| Comando | Descripción |
|---|---|
| `note add --content "..."` | Captura una nota privada. `--content` acepta `@file`. |

`--allow-secrets` y `--json` están disponibles. Una nota siempre es privada para ti.

## Audit y export

| Comando | Descripción |
|---|---|
| `audit log [--limit <n>]` | El registro de auditoría del workspace (owner/admin). |

El export del workspace es una capacidad owner/admin, pero el endpoint de export requiere una sesión humana del dashboard, así que córrelo desde el dashboard en vez de una llamada de CLI con API key.
