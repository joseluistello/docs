Los sistemas externos se alcanzan mediante MCP a través de **tools de conector sintetizadas**: una
conexión de provider lista expone `<provider>_records` y
`<provider>_document_content` en `tools/list`. Operan una [Connection](/es/integrations/overview) que ya existe, y nunca conectan ni desconectan una (el setup es un flujo humano en el dashboard o el CLI, no en la superficie de MCP). Si un agente necesita datos que la tool no expone, debe reportar la capability faltante, nunca improvisar un script.

El router genérico `broker` (la tool basada en actions `connections` / `operations` / `invoke` / `records` / `index`) no tiene **ninguna tool de MCP** — su definición y handler fueron eliminados, no sólo ocultos — una llamada legacy `driftless_broker` ahora responde "Unknown tool". Sigue disponible mediante el CLI y el dashboard.

<Warning>
El Broker está **gated**: apagado por defecto en producción (`DRIFTLESS_BROKER_ENABLED`), con un lane externo separado (`DRIFTLESS_BROKER_ROLLOUT`) y grants por principal. Que una tool esté listada no la vuelve usable: un caller externo de OAuth/MCP sin faceless grant recibe un resultado vacío incluso contra una conexión saludable.
</Warning>

## Tools de conector sintetizadas

| Tool | Propósito | Efecto |
| --- | --- | --- |
| `<provider>_records` | Leer los records de un modelo sincronizado desde el mirror (página acotada, delta-aware) | lectura |
| `<provider>_document_content` | Leer el texto acotado y citable de un documento, en vivo (cualquier provider de contenido) | lectura |

```text
notion_records model:'ContentMetadata' limit:5
notion_document_content external_id:'<id>'
```

## Gates y permisos

Se aplican tres gates independientes y fail-closed a un caller externo, en orden: el
switch maestro (`DRIFTLESS_BROKER_ENABLED`), el lane externo (`DRIFTLESS_BROKER_ROLLOUT`),
y un grant por principal. Una operación también debe estar permitida por política; en
producción el registro de políticas sale vacío, así que ninguna escritura es invocable.

| Scope | Cubre |
| --- | --- |
| `broker:read` | Lecturas del conector (`records`, `document-content`) |
| `broker:invoke` / `broker:admin` | Las actions de escritura/admin del router genérico del broker (eliminadas del catálogo de MCP; sólo CLI/dashboard) |

Los scopes `broker:*` se aplican sólo cuando el Broker está habilitado, y gobiernan el
lane encima del rollout y los grants. Un caller interno (una API key propia o una
sesión de dashboard) se salta el gate de grant pero igual necesita el resto.

## Disponibilidad

| Capability | Estado |
| --- | --- |
| Tools de lectura sintetizadas por workspace (`<provider>_records`, `<provider>_document_content`) | Disponibles sólo cuando la síntesis está habilitada y una capability está `ready` |
| Síntesis de capabilities de escritura | No disponible (nunca se sintetiza) |
| Router genérico `broker` en `tools/list` | Eliminado — no tiene ninguna tool de MCP |
