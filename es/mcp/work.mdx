CRM es el sistema operativo de registro de Brein: Prospectos (Collections/Records) guarda cuentas, oportunidades y seguimiento. Las tools de MCP son basadas en actions, acotadas por defecto, y usan los mismos contratos de servidor que el dashboard y el CLI. Las lecturas son de nivel miembro; las escrituras de ciclo de vida requieren `work:write`. El CRUD genérico de schema/config de Collection y el purge permanente no tienen tool de MCP — configurar un pipeline es trabajo humano, y ninguna tool de agente borra.

## Records

Usa `collection_query` para lecturas acotadas (estado `ok` / `continue` / `incomplete`, nunca concluyas cobertura por una sola página). Antes de actuar sobre un record, lee el criterio de la Collection con `context_get` sobre sus `criterion_refs` — el criterio es lo que el equipo aplica a esos records.

| Tool | Actions principales | Propósito |
| --- | --- | --- |
| `collection_query` | `query`, `get`, `aggregate` | Leer records acotados con proyección, filtros y continuación explícitos |
| `crm_record` | `add`, `update`, `history`, `bulk`, `schedule_activity` | Crear o avanzar records tipados; el status debe coincidir con el ciclo de vida de la Collection. Renombrada desde `collection_record` (MCP · 2) — las lecturas (`list`/`get`) ya no están en su enum de actions, usa `collection_query` |

```text
collection_query op:'query' collection_id:'<collection-id>' limit:25
  → { status:'ok'|'continue'|'incomplete', data:[ ... ], page_info:{ ... } }
```

## Retirado del catálogo público

La configuración de schema de Collection (`collection`), el purge permanente
(`collection_purge`), el borrado de records (`collection_record_delete`)
y el registro de entidades (`entity`) no tienen ninguna tool de MCP — sus
definiciones y handlers fueron eliminados, no sólo ocultos; una llamada legacy
`driftless_*` ahora responde "Unknown tool". La configuración de schema sigue
siendo una superficie humana de dashboard/CLI; la resolución de identidad
ocurre del lado del servidor al guardar un record.

## Permisos

| Scope o rol | Cubre |
| --- | --- |
| lectura de miembro | Lecturas de Collection y Record, contexto de criterio, historial |
| `work:write` | Crear y actualizar Records; escrituras de ciclo de vida |

Los clientes MCP cachean schemas de tools por sesión de conector. Reconecta el conector después de una actualización para que los tools eliminados o cambiados se reflejen en el cliente.
