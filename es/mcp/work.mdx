Collections son el sustrato operativo de Driftless: pipelines, filas de CRM, trackers y trabajo estructurado. Sus tools MCP usan actions, son acotadas por defecto y comparten los mismos contratos del dashboard y la CLI. Las escrituras requieren `work:write`; purgar una Collection requiere además una identidad humana owner/admin.

## Collections y records

Usa `driftless_collection_query` para lecturas acotadas. Antes de actuar sobre un Record, carga el criterion con `driftless_collection action:'context'`; devuelve el Knowledge que gobierna cómo trabaja el equipo esos registros.

| Tool | Actions principales | Propósito |
| --- | --- | --- |
| `driftless_collection` | `search`, `list`, `get`, `add`, `update`, `archive`, `restore`, `doctor`, `context`, `presentation` | Configura e inspecciona una Collection; `get` es brief salvo que pidas `view:'full'` |
| `driftless_collection_query` | `query`, `get`, `aggregate` | Lee Records acotados con proyección, filtros y continuación explícitos |
| `driftless_collection_record` | `add`, `update`, `history` | Crea o avanza Records tipados; el status debe existir en el lifecycle de la Collection |
| `driftless_collection_purge` | una llamada gobernada | Previsualiza con `dry_run` y confirma con `expected_version`; solo owner/admin |
| `driftless_collection_record_delete` | una llamada gobernada | Previsualiza y elimina un Record sin borrar sus Notes destiladas |

```text
driftless_collection action:'context' id:'<collection-id>'
  → { criterion: [ ... ], criterion_missing: [] }

driftless_collection_query action:'query' collection_id:'<collection-id>' limit:25
  → { status:'ok'|'continue'|'incomplete', data:[ ... ], page_info:{ ... } }
```

## Entities

Una Entity es una identidad entre Collections que los Records pueden referenciar. `driftless_entity action:'upsert'` es idempotente sobre `(kind, dedup_key)`.

```text
driftless_entity action:'upsert' kind:'company' name:'Acme' dedup_key:'acme.com'
```

## Permisos

| Scope o rol | Cubre |
| --- | --- |
| lectura de member | Lecturas de Collections y Records, criterion, history y doctor |
| `work:write` | Crear y actualizar Collections, Records y Entities; archive y restore de Collections |
| owner/admin | Purga permanente de una Collection |

Los clientes MCP guardan los schemas de tools por sesión. Reconecta el connector después de actualizar para reflejar tools eliminadas o modificadas.
