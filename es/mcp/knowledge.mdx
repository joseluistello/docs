Este es el plano de Cerebro sobre MCP: las herramientas que un cliente de IA usa para leer el criterio comercial del equipo antes de actuar (oferta, ICP, exclusiones, señales, geografía, compradores, mensajes y playbooks) y para mantenerlo. Para configuración, autenticación y los scopes de OAuth referenciados abajo, consulta [MCP y OAuth](/es/mcp/overview).

Las tools públicas usan nombres de capability neutrales, sin prefijo de producto. Sus aliases `brein_*` y `driftless_*` resuelven a la misma tool pero no se anuncian en `tools/list`.

## Recuperación y lectura

Empieza con `context_retrieve` cuando tienes una tarea pero no un slug. Los cuerpos vuelven **brief** por defecto (el porqué durable, no el `content` completo); trae un cuerpo completo con `context_get`.

| Tool | Propósito | Parámetros principales | Devuelve |
| --- | --- | --- | --- |
| `context_retrieve` | Contexto ordenado para una tarea y/o archivos — absorbe full-text search, listado y match de archivos (MCP · 2) | `task`, `files`, `tags`, `area`, `stale`, `status`, `view`, `limit` | `{ shown, has_more, next_action, results[] }` |
| `context_get` | Un topic por slug (cuerpo completo) | `topic`, `view` | el topic completo |

`context_search`, `context_list` y `context_get_for_files` ya no aparecen en `tools/list` — `context_retrieve` ya tomaba sus argumentos (`query`→`task`, `status`/`stale`/`tags`, `files`). Siguen resolviendo durante 60 días como aliases ocultos de compatibilidad (su resultado nombra el reemplazo en `next_action`); después de esa ventana responden "Unknown tool".

Permiso: `context:read`. Disponibilidad: disponible.

```text
context_retrieve task:'endurecer el webhook' files:['src/webhooks/handler.ts']
  → { results: [ { slug, trust, why_matched, confidence } ], has_more }
```

## Escritura y edición

| Tool | Propósito | Parámetros principales | Notas |
| --- | --- | --- | --- |
| `context_create` | Crear un documento de criterio | `title`, `content`, `area` | el documento nace compartido en el workspace — no hay cola de revisión en ninguna parte (MCP · 2) |
| `context_update` | Actualización append-safe | `topic`, campos | devuelve `anchor_validation` |

Permisos: `topics:create` / `topics:write`. Disponibilidad: disponible. Las respuestas de escritura llevan `anchor_validation` (`ok` / `overbroad` / `zero`), que nunca bloquea la escritura. Ninguna tool de agente borra un topic ni publica una página pública — ver más abajo.

## Retirado del catálogo público

Las siguientes superficies no tienen ninguna tool de MCP — sus definiciones y handlers
fueron eliminados, no sólo ocultos; una llamada legacy `driftless_*` ahora responde
"Unknown tool". Su curación sigue disponible para los owners mediante el CLI y
el dashboard:

- Notas como producto independiente (`note_add`);
- grafo de topics (`context_graph`) y relaciones (`context_relations`);
- comentarios (`context_comment`);
- la gobernanza Nota→Knowledge retirada (`context_propose`, `_approve`,
  `_create_proposal`, `_proposals`, `_merge`) — no hay nada que aprobar;
- eventos y doctor (`context_events`, `_doctor`);
- areas y tags (`areas`, `tags`);
- borrado (`context_delete`) — ninguna tool de agente borra un topic;
- publicar a la web (`context_share`) — publicar es trabajo humano, no una acción de agente.

## Permisos

| Scope | Cubre |
| --- | --- |
| `context:read` | Leer topics, retrieve, search, list |
| `topics:create` | Crear topics |
| `topics:write` | Actualizar topics existentes |
| `context:diff` | Leer el diff de topics para cambios locales |
