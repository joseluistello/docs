Los errores de la API de Brein usan un sobre JSON estable en REST, CLI y MCP. Ramifica según el `code` legible por máquina; usa `message` sólo para contexto humano.

## El sobre

```json
{
  "statusCode": 422,
  "code": "VALIDATION_FAILED",
  "message": "The request contains a field value the server cannot accept.",
  "request_id": "a1b2c3d4",
  "retryable": false,
  "endpoint": "POST /api/v1/workspaces/acme/..."
}
```

| Campo | Significado |
|---|---|
| `statusCode` | Estado HTTP. |
| `code` | Código estable y legible por máquina. Los códigos nuevos son aditivos. |
| `message` | Contexto humano. Puede cambiar; no lo parsees. |
| `request_id` | Id de correlación. Inclúyelo en reportes. |
| `retryable` | `true` sólo cuando la operación puede funcionar después. Un `4xx` definitivo no se reintenta. |
| `endpoint` | Método y ruta que produjeron el error. |

Algunos dominios agregan un bloque tipado. Market Data, por ejemplo, puede agregar `market_data` con un código semántico, la razón del rechazo, una corrección sugerida y una acción de recuperación de vocabulario cerrado.

## Categorías comunes

### Validación e input

- `VALIDATION_FAILED` — un campo falló la validación.
- `BAD_REQUEST` — petición inválida genérica sin código más específico.
- `INVALID_VALUE` — el valor viola una restricción del servidor o base de datos.
- `INVALID_ID` — el identificador está mal formado.
- `REQUIRED_FIELD` — falta un campo requerido.
- `FK_VIOLATION` — el registro referenciado no existe.
- `SECRET_DETECTED` — una escritura parecía contener una credencial y fue bloqueada; el error no repite el secreto.

### Acceso y scope del workspace

- `UNAUTHORIZED` — falta la API key o el token no es válido.
- `FORBIDDEN` — el caller está autenticado pero no tiene permiso.
- `INSUFFICIENT_ROLE` — el caller no tiene el rol requerido.
- `NOT_FOUND` — el recurso no está disponible para ese caller.
- `METHOD_NOT_ALLOWED` — la ruta existe pero el verbo no; sigue el header `Allow`.

### Saldo comercial

- `COMMERCIAL_CALL_LIMIT_REACHED` — el workspace agotó sus requests comerciales incluidos.
- `COMMERCIAL_CREDITS_EXHAUSTED` — no quedan créditos de inteligencia.
- `COMMERCIAL_CREDITS_INSUFFICIENT` — la acción solicitada supera el allowance restante.

Estas respuestas incluyen el estado de uso actual y una siguiente acción cuando el workspace necesita un plan o decisión comercial. Un allowance agotado es un `402` definitivo; no lo reintentes como si fuera un fallo transitorio.

### Conflictos y fallos del servidor

- `DUPLICATE` o `DUPLICATE_TOPIC` — el recurso ya existe.
- `VERSION_CONFLICT` — el objeto cambió después de leerlo; vuelve a leer y reaplica el cambio.
- `RATE_LIMITED` — reduce el ritmo y sigue la guía de retry.
- `INTERNAL` — fallo inesperado; conserva el `request_id` al reportarlo.

## La gobernanza retirada no es un ejemplo de error

El ciclo anterior Note → Knowledge de aprobación y merge está retirado. No uses una ruta `approve` o `merge` como ejemplo canónico de identidad, autorización o manejo de errores. Las escrituras actuales usan el contrato de documentos, CRM, mercado, research o campañas.
