Todas las rutas están bajo `/api/v1` y requieren autenticación. El uso customer-facing del CRM es contact-first: una Collection contiene personas que el workspace adquirió y archivó explícitamente. Una empresa, fila de mercado o evidencia no se convierte en Record sólo porque exista un endpoint Record genérico.

## Collections

| Método | Ruta | Propósito |
|---|---|---|
| `POST` | `/workspaces/:slug/collections` | Crea una Collection configurada y orientada a contactos. |
| `GET` | `/workspaces/:slug/collections` | Lista Collections active y acotadas. |
| `GET` | `/workspaces/:slug/collections/search` | Busca Collections por intención. |
| `GET` | `/workspaces/:slug/collections/:id` | Lee una Collection con `view=brief|full`. |
| `PATCH` | `/workspaces/:slug/collections/:id` | Actualiza configuración segura. Los cambios de lifecycle usan rutas explícitas. |
| `POST` | `/workspaces/:slug/collections/:id/archive` | Retira una Collection de forma reversible. |
| `POST` | `/workspaces/:slug/collections/:id/restore` | Restaura una Collection archivada. |
| `DELETE` | `/workspaces/:slug/collections/:id` | Purge permanente owner/admin después de dry-run/version. |

El servidor controla la forma de contacto y valida el lifecycle. No uses una ruta genérica de configuración para convertir una empresa, observación de proveedor, licitación, adjudicación, permiso o resultado de research en un contacto CRM.

## Records de contacto

Ruta base: `/workspaces/:slug/collections/:id/records`.

| Método | Ruta | Propósito |
|---|---|---|
| `POST` | `.../records` | Crea un Record sólo mediante el camino autorizado de archivo de contacto. |
| `GET` | `.../records` | Página acotada de Records activos. |
| `GET` | `.../records/:recordId` | Lee un Record de contacto. |
| `PATCH` | `.../records/:recordId` | Actualiza un Record existente y su estado. |
| `DELETE` | `.../records/:recordId` | Borrado gobernado explícito; nunca extracción masiva. |

Un flujo customer-facing normal llega a la creación mediante el camino Radar/personas: buscar, cotizar las personas seleccionadas, confirmar explícitamente, revelar/importar y archivar el contacto elegido. Un write Record REST genérico no debe saltarse esa selección y autorización.

Los estados se validan contra las etapas configuradas. `entity_id` es una propiedad top-level de compatibilidad, no una forma de adjuntar una empresa no verificada a una persona.

## Entities

Las rutas de Entity siguen disponibles para consumidores técnicos activos y resolución de identidad compartida. No son una tool MCP pública y no prueban que un nombre aproximado o URL del cliente sea la identidad de una empresa.

## Paginación y errores

Las lecturas de Collection y Record usan páginas acotadas y cursores opacos. Sigue `nextCursor` antes de concluir cobertura. Campos, estados o filtros inválidos devuelven el [sobre de error](/es/api/errors) actual.

## Lifecycle

`archive` y `restore` son operaciones reversibles separadas. `purge` es permanente, sólo owner/admin, auditado y debe previsualizarse con su contrato actual de dry-run/version. Un cambio de estado nunca hace archive o purge silenciosamente.
