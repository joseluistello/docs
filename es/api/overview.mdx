URL base:

```text
https://api.trybrein.com/api/v1
```

## Autenticación

Los recursos de workspace requieren API key, sesión Clerk o token OAuth autorizado. Una credencial ausente o inválida devuelve `401`; un caller autenticado sin el scope requerido devuelve `403`.

```bash
curl https://api.trybrein.com/api/v1/me \
  -H "x-api-key: drift_your_api_key_here"
```

Trata las API keys como secretos. Brein las guarda cifradas y muestra el valor crudo sólo al crearlas.

## Recursos del workspace

| Recurso | Rutas principales | Trabajo del cliente |
|---|---|---|
| Workspace y equipo | `/workspaces/:slug`, `/members`, `/api-keys` | Administra workspace, personas, roles y credenciales con scope. |
| Uso comercial | `/workspaces/:slug/commercial-usage` | Lee plan, requests, créditos de inteligencia, créditos de contacto, renovación y acción de upgrade. |
| Documentos de Cerebro | `/workspaces/:slug/documents/*` | Lee y escribe documentos markdown en carpetas. |
| CRM | `/workspaces/:slug/collections/*` | Opera Records de contactos y su ciclo acotado. |
| Empresas y personas | `/workspaces/:slug/radar/*` | Busca empresas, descubre personas enmascaradas, revela seleccionadas, gestiona contactos adquiridos y los archiva. |
| Listas | `/workspaces/:slug/radar/lists/*` | Guarda, refresca, cotiza, revela y exporta un resultado de búsqueda de personas. |
| Market Data | `/workspaces/:slug/market-data/*` | Ejecuta operaciones tipadas y de sólo lectura de proveedores, oportunidades, adjudicaciones, riesgos y permisos. |
| Explorer | `/workspaces/:slug/intelligence/explorer/*` | Busca e inspecciona el explorer de empresas/evidencia del cliente. |
| Research | `/workspaces/:slug/research/*` | Inicia, inspecciona, transmite y cancela corridas durables de Investigador. |
| Email y campañas | `/workspaces/:slug/email-campaigns/*`, `/email-mailboxes/*` | Prepara, revisa, autoriza, activa, pausa y mide secuencias. |
| Integraciones | `/workspaces/:slug/integrations/*` | Lista, conecta, confirma, reconecta y desconecta providers. |
| Broker | `/workspaces/:slug/broker/*` | Inspecciona y ejecuta operaciones gobernadas sobre una conexión existente. |

Cada ruta de workspace está acotada al workspace y autenticada. Un caller no puede usar la key o ruta de un workspace para leer datos de otro.

## Rutas públicas de infraestructura

La superficie pública es intencionalmente pequeña. Incluye health y version, bootstrap inicial del workspace, contenido público del sitio, endpoints OAuth de discovery/register/token, receptores de webhooks firmados, endpoints de unsubscribe/share y otras rutas explícitamente públicas.

La allowlist pública exacta la poseen la API y sus decoradores de ruta; no infieras que un recurso es público porque un cliente no muestre sesión. Consulta [Errores](/es/api/errors) para el sobre común y [Seguridad](/es/security/overview) para los límites de datos.

## Límite entre mercado y activación

El análisis de mercado es separado de la activación de contactos:

- lecturas, conteos, comparaciones, historial y agregados de mercado no gastan créditos;
- un detalle de empresa que realmente devuelve una coordenada publicada puede gastar un crédito de inteligencia;
- la revelación de contactos es persona-primero, se cotiza para el grupo seleccionado, requiere confirmación separada y se cobra contra el saldo separado de contactos;
- una revelación vacía o fallida se reembolsa y nunca activa un fallback automático.

Las respuestas comerciales exitosas exponen el estado de uso actual. Un allowance agotado falla cerrado con un `402` accionable; no se convierte en una cancelación genérica.

## Superficies de compatibilidad

La API conserva montadas algunas rutas de Topics, sharing, relations y CLI legacy. No son el modelo principal del cliente. El modelo actual de Cerebro son documentos en carpetas; el CRM actual son Records centrados en contactos; y el catálogo MCP actual usa nombres neutrales. Las filas y rutas históricas pueden permanecer hasta que sus consumidores migren, pero compatibilidad no crea una nueva superficie de producto.
