Brein puede soportar el contexto de ingeniería de un equipo de software mediante documentos de Cerebro y anclas de rutas. Es un caso de uso secundario, separado del journey comercial del cliente.

## El loop de ingeniería

1. **Recupera antes de editar.** Usa la CLI o las tools MCP actuales:

   ```bash
   driftless context get --files "src/auth/guard.ts,src/auth/service.ts"
   driftless context get <document>
   ```

   En MCP, empieza con `context_retrieve` y luego llama `context_get` para el único documento completo que necesites. Lee el porqué durable —decisiones, gotchas, invariantes y vigencia— antes de cambiar código.

2. **Crea o reescribe un documento limpio.** Si ningún documento cubre el área, crea uno con `driftless context add` o `context_create`. Si ya existe, léelo y consolida el dato nuevo con `context write` o `context_update`. Un documento nace compartido con el workspace; no hay una cola Note → Knowledge.

3. **Usa anclas estrechas.** Un documento de código puede apuntar a un conjunto pequeño y explícito de rutas o globs. Una anchor demasiado amplia o sin coincidencias es una señal para corregir el documento, no para afirmar que el código está cubierto.

4. **Persiste sólo conocimiento durable.** No conviertas una transcripción de comandos, una tarea temporal o un valor de una sola vez en documento. La pregunta es si un cambio futuro contradiría de forma significativa la afirmación.

5. **Reconecta después de cambios de schema.** Los clientes MCP cachean definiciones por sesión. Inicia una sesión nueva o reconecta el conector después de un cambio.

## Archivos instalados

```bash
pnpm add -g @driftless-sh/cli
# o
npm install -g @driftless-sh/cli
driftless login
driftless install-skill
```

`install-skill` escribe los bloques gestionados de `AGENTS.md` y `CLAUDE.md`, además de `.driftless/skill.md`, para los agentes de código soportados. Vuelve a correrlo después de actualizar la CLI si quieres refrescar las instrucciones instaladas.

## Lee la superficie MCP actual

Usa nombres neutrales como `context_retrieve`, `context_get`, `context_ls`, `context_read`, `context_write`, `context_search`, `collection_query`, `crm_record`, `people_file` y `sequence_activate`.

No construyas una integración nueva alrededor de tools retiradas como `driftless_context_search`, `driftless_context_create`, `driftless_collection`, `driftless_tags` o `driftless_areas`. Los aliases ocultos existen sólo durante la ventana de compatibilidad documentada; no son el catálogo actual.

## Seguridad comercial

El skill de ingeniería no autoriza revelar contactos, gastar créditos, enviar emails ni tomar decisiones CRM importantes. Esas operaciones tienen sus propios scopes server-side, selecciones explícitas, confirmaciones y requisitos de auditoría. Consulta [MCP: Sequences](/es/mcp/sequences) y [El workspace de Brein](/es/product/workspace).
