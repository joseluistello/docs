The Architecture Map is an interactive graph that visualizes your repo's module structure, dependency relationships, and context coverage at a glance.

## Graph Engine

The map is built with **ReactFlow** for graph rendering and **dagre** for automatic layout. Nodes represent modules, edges represent relationships.

### Nodes — Modules

Each node is a module (directory or logical group of components). Node size is proportional to component count. Color encodes coverage status:

| Color | Coverage state |
|---|---|
| **Green** | Covered — at least one up-to-date topic exists |
| **Yellow** | Partial — a topic exists but is stale or only covers some files |
| **Red** | Gap / Critical gap — no topic assigned |
| **Gray** | No topics — no context has been created for this module |

### Edges — Relations

Edges connect modules that have relationships: module imports, service injections, guard usage, and other structural dependencies detected by the scanner.

## Three-panel layout

| Panel | Content |
|---|---|
| **Module Tree (left)** | Searchable, collapsible file-tree of all modules with component counts |
| **Graph Canvas (center)** | Interactive node-link diagram — zoom, pan, click to explore |
| **Component Detail (right)** | Click a module → list of components (endpoints, services, guards) with their relations. Click a component → full detail popup with metadata |

## Coverage Filters

Toggle coverage states to filter the graph and module tree simultaneously:

- Covered
- No-topics
- High-risk
- Reviewed-stale
- Draft-suggested

Multiple states can be shown or hidden at once.

## Focus Mode

Click a module to focus the graph — all other nodes are hidden, showing only the selected module and its direct neighbors. Use this to inspect the blast radius of a change before you make it. Click **Exit focus** to return to the full graph.

## Coverage Overlay

Toggle the coverage overlay to highlight modules missing context with a red border. This is the fastest way to spot coverage gaps across the entire repo.

## Smart-init Signals

From the map, you can act on modules directly:

| Action | Description |
|---|---|
| **Create topic** | Generate a new topic anchored to the selected module |
| **Link topic** | Associate an existing topic with the module |
| **Unlink topic** | Remove a topic association |
| **Promote** | Mark a draft topic as reviewed |
| **Reject** | Remove an auto-generated topic |

## Rescan

A **Rescan** button in the toolbar re-triggers the scanner for the selected repo. The graph updates with fresh component data after the scan completes.
