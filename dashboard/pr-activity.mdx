The PR Activity panel logs every pull request observed by the GitHub App. Each row shows the full chain: files changed, topics matched, and whether a context comment was posted.

## PR Table

| Column | Description |
|---|---|
| **PR #** | Pull request number with link to GitHub |
| **Title** | PR title |
| **Author** | GitHub username |
| **Branch** | Source branch name |
| **Files touched** | Number of changed files |
| **Topics matched** | Number of topics whose patterns overlap with changed files |
| **Comment status** | `posted`, `no_match`, or `error` |
| **Risk** | Inferred risk level based on matched topics |
| **Observed date** | When the webhook was received |

## Filters

| Filter | Options |
|---|---|
| **Status** | Dropdown: `all`, `posted`, `no_match`, `error` |
| **Branch** | Free-text branch name filter |

## Detail Panel

Click any row to open the detail panel, which shows:

- **Matched topics** — each with a link to the topic detail page
- **Files touched** — complete list of changed files
- **GitHub PR link** — direct link to the pull request on GitHub

## KPI Summary

The top of the page shows aggregate counts:

| KPI | Description |
|---|---|
| **Observed** | Total PRs received |
| **Matched** | PRs where at least one topic matched |
| **Posted** | PRs where a context comment was successfully posted |
| **Updated** | PRs where an existing comment was updated |
| **No-match** | PRs with zero topic matches |
| **Failed** | PRs where comment posting errored |

## PR Flow Diagram

The canonical flow from webhook to comment:

<Steps>
  <Step title="GitHub App receives webhook">
    Triggered on `pull_request.opened`, `synchronize`, `reopened`, or `ready_for_review`.
  </Step>
  <Step title="API resolves workspace">
    The installation ID from the webhook is mapped to the correct workspace.
  </Step>
  <Step title="Fetch PR files">
    Driftless fetches the list of changed files via the GitHub API using a short-lived installation token.
  </Step>
  <Step title="Match files against topics">
    Each changed file is checked against every topic's file patterns and `where_files`.
  </Step>
  <Step title="Post or update sticky comment">
    Matched topics are posted as a single comment on the PR. If a comment already exists (identified by the `<!-- driftless-context -->` marker), it's updated in place rather than re-posted.
  </Step>
</Steps>

## Status details

### No-match

No topic patterns matched the changed files. The PR touches areas with no documented context. Consider creating a topic for those files.

### Error

The comment could not be posted. Common causes: GitHub App not installed on the repo, missing permissions, API rate limiting, or temporary GitHub outage.

<Note>
  Requires the GitHub App. The PR Activity panel is empty until the first observed PR. See [GitHub App Integration](/integrations/github-app) to install and connect.
</Note>
