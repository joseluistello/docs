The dashboard is the visual companion to the CLI. Use it when you need workspace-level visibility instead of terminal output.

## Main areas

| Area | Use it for |
|---|---|
| Overview | Workspace repositories and setup state |
| Knowledge | The **Knowledge** graph — the notes merged in (reviewed topics only) |
| Review queue | The merge queue — Notes up for review + re-review of drifted Knowledge |
| Notes | Your **private** workspace — draft notes only you see, with share controls |
| Topic Graph | Visualize topic relationships (depends_on, relates_to, supersedes, etc.) — pick a tag to light up that category (everything else dims) |
| PR Activity | See observed pull requests and context matches |
| Settings | Manage API keys, GitHub integration, OAuth apps, members, and the tag registry |

**Tags filter every list surface**: tag chips on Knowledge (most-used first, with counts), a tag select on the Inbox tab row, and the tag scope on the Topic Graph. Manage the vocabulary itself in **Settings → Tags** — register a tag with a description before any topic uses it, rename it everywhere (rewrites the topics that carry it), or delete it (detaches from every topic).

The three surfaces mirror the one-topic-that-evolves model ([Governance](/concepts/governance)): **Note → Up for review → Knowledge**.

## Review queue

Where a **Note up for review is added to Knowledge**. Two lanes:

- **Pending review** — Notes up for review (`proposed`). Merge to add it to Knowledge, or **send back with a reason** (the author sees it on their draft).
- **Needs re-review** — Knowledge whose code **drifted**. Confirm it still holds (clears the drift flag) or open to update.

Inbox-zero means your team's memory is healthy. Merging follows [workspace roles](/concepts/governance#who-can-merge--workspace-roles) — only admins/owners merge.

## Notes

Your **private** scratch: draft topics only you can see, excluded from search. Put a Note up for review when it's ready for the team. Untouched Notes auto-archive after ~14 days (recoverable, never deleted).

## Context detail

Each topic has a detail page with:

- What, how, decisions, gotchas, and invariants
- Anchored files, patterns, repos, and documents
- Stale status and reason
- References and backlinks from wiki-links
- Typed relations (depends_on, relates_to, supersedes, etc.)
- Copy for AI output for agent prompts

## Settings

Use settings to manage:

- API keys for CLI and CI
- GitHub App installation
- OAuth apps (MCP integrations for ChatGPT, Claude, and other AI clients)
- Workspace members and invitations
- The tag registry — pre-create, describe, rename, or delete the workspace's category tags
- BYOM model URL, key, and model name

<Note>
  Driftless never hardcodes a model provider. Workspace model configuration controls any model-backed behavior.
</Note>

## MCP integrations

The dashboard includes an OAuth consent screen at `/oauth/authorize` for authorizing MCP client applications (ChatGPT, Claude, and other AI tools) to access your workspace context. See [Roadmap](/roadmap) for details on MCP and OAuth support.
