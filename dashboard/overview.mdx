The dashboard is the visual companion to the CLI. Use it when you need workspace-level visibility instead of terminal output.

## Main areas

| Area | Use it for |
|---|---|
| Overview | Workspace repositories and setup state |
| Context | The **Institutional Context** graph — vouched, reviewed topics only |
| Proposals | The approve/reject queue — pending Proposals + re-review of drifted context |
| Notes | Your **private** workspace — draft notes only you see, with share controls |
| Topic Graph | Visualize topic relationships (depends_on, relates_to, supersedes, etc.) |
| PR Activity | See observed pull requests and context matches |
| Settings | Manage API keys, GitHub integration, OAuth apps, and members |

The three surfaces mirror the one-topic-that-evolves model ([Governance](/concepts/governance)): **Note → Proposal → Institutional Context**.

## Proposals

Where a **Proposal becomes Institutional Context**. Two lanes:

- **Pending review** — Proposals (`proposed`) routed to the projects you can vouch in. Approve to vouch into the graph, or **send back with a reason** (the author sees it on their Note).
- **Needs re-review** — Institutional Context whose code **drifted**. Confirm it still holds (clears the drift flag) or open to update.

Inbox-zero means your team's memory is healthy. Vouching follows [project roles](/concepts/governance#who-can-vouch--project-roles) — only maintainers/owners approve in private projects.

## Notes

Your **private** scratch: draft topics only you can see, excluded from search. Promote a note to a **Proposal** when it's ready for the team, or **share** it to the project for early feedback. Untouched notes auto-archive after ~14 days (recoverable, never deleted).

## Context detail

Each topic has a detail page with:

- What, how, decisions, gotchas, and invariants
- Anchored files, patterns, repos, and documents
- Stale status and reason
- References and backlinks from wiki-links
- Typed relations (depends_on, relates_to, supersedes, etc.)
- Copy for AI output for agent prompts

## Settings

Use settings to manage:

- API keys for CLI and CI
- GitHub App installation
- OAuth apps (MCP integrations for ChatGPT, Claude, and other AI clients)
- Workspace members and invitations
- BYOM model URL, key, and model name

<Note>
  Driftless never hardcodes a model provider. Workspace model configuration controls any model-backed behavior.
</Note>

## MCP integrations

The dashboard includes an OAuth consent screen at `/oauth/authorize` for authorizing MCP client applications (ChatGPT, Claude, and other AI tools) to access your workspace context. See [Roadmap](/roadmap) for details on MCP and OAuth support.
