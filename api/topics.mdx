title: 'Topics and Cerebro documents'

---

Cerebro is the current customer-facing document model. The dashboard and current document API use markdown documents in folders. The older Topics API remains mounted for compatibility, but its governance and graph language is not the current customer workflow.

## Current Cerebro document routes

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/workspaces/:slug/documents/tree` | Browse the document tree. |
| `GET` | `/workspaces/:slug/documents/file` | Read one document by folder/path. |
| `PUT` | `/workspaces/:slug/documents/file` | Create or replace a document. |
| `GET` | `/workspaces/:slug/documents/search` | Search document content within the workspace. |

A document is born shared with the workspace. There is no Note → Knowledge approval queue in the current customer model. To change durable commercial context, read the current document and rewrite the consolidated body.

## Topics compatibility routes

These routes remain available for existing technical clients:

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/workspaces/:slug/topics` | List topics. |
| `POST` | `/workspaces/:slug/topics` | Create a topic-shaped document record. |
| `GET` | `/workspaces/:slug/topics/:topic` | Read one topic. |
| `PATCH` | `/workspaces/:slug/topics/:topic` | Update one topic. |
| `DELETE` | `/workspaces/:slug/topics/:topic` | Delete a topic through the compatibility API. |

`status`, `trust`, proposal, and governance fields may remain in historical responses for compatibility, but they do not create an active approval workflow. Do not branch a new customer integration on them.

## Search and path matching

The compatibility Topics surface also retains bounded search and path matching:

- `GET /workspaces/:slug/topics/search`
- `POST /workspaces/:slug/topics/match-files`
- `GET /workspaces/:slug/topics?stale=true|false`

Engineering path anchors remain useful for software teams, but they are not the commercial product's center.

## Retired governance

The former Note → Knowledge verbs and proposal lifecycle are retired. Routes such as `propose`, `approve`, `reject`, proposals, and merge are compatibility no-ops where they still exist; they do not move a document through a review state. Use the document update path or the CLI context commands instead.

The topic graph, manual relations, and customer-facing governance chrome are not part of the current Cerebro customer workflow. They may remain in storage or technical compatibility surfaces for consumers that have not migrated.

## Visibility and sharing

A document's workspace visibility and public sharing are separate from the retired governance model. The CLI and dashboard own the human-facing sharing controls; the current public MCP catalog does not expose topic delete, publishing, graph, relations, comments, or proposal tools.
