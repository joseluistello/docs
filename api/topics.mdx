<Note>
The canonical path is `/topics`. `/watchers` still works as a deprecated alias for old CLIs and is removed in a later release.
</Note>

## Core CRUD

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/workspaces/:slug/topics` | List topics (visible to the caller) |
| `POST` | `/workspaces/:slug/topics` | Create a topic (assigned to a project; `project_id` optional) |
| `GET` | `/workspaces/:slug/topics/:topic` | Get topic detail |
| `PATCH` | `/workspaces/:slug/topics/:topic` | Update a topic (incl. `project_id` to move it) |
| `DELETE` | `/workspaces/:slug/topics/:topic` | Delete a topic |

The read response is the canonical context. It includes `classification.status` and a `governance` block — the trust signal an agent consumes:

```json
{
  "classification": { "status": "reviewed", "kind": "reference" },
  "governance": { "reviewed": true, "approved_by": "u_cto", "approved_at": "..." }
}
```

## Governance

A topic is reviewed only if approved. See [Governance](/concepts/governance). `approve` / `reject` and proposal `merge` / `reject` require a human identity.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/workspaces/:slug/topics/:topic/propose` | `draft → proposed` |
| `POST` | `/workspaces/:slug/topics/:topic/approve` | `→ reviewed` (reviewed) |
| `POST` | `/workspaces/:slug/topics/:topic/reject` | `proposed → draft` |
| `POST` | `/workspaces/:slug/topics/:topic/archive` | `→ archived` |
| `GET` | `/workspaces/:slug/topics/:topic/proposals` | List topic-PRs |
| `POST` | `/workspaces/:slug/topics/:topic/proposals` | Open a topic-PR (`{ summary, patch }`) |
| `POST` | `/workspaces/:slug/topics/:topic/proposals/:id/merge` | Apply + approve a topic-PR |
| `POST` | `/workspaces/:slug/topics/:topic/proposals/:id/reject` | Close a topic-PR |
