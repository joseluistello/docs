The graph endpoints provide deterministic code intelligence: file-level component graphs, impact analysis (blast radius), and agent-facing context loading.

## File Graph

Get the component-level graph for a specific file:

```bash
curl -H "X-API-Key: drift_xxx" \
     "https://api.driftless.icu/api/v1/workspaces/my-team/repos/repo_uuid/graph/file?path=src/auth/guard.ts&depth=3"
```

<ParamField query="query" type="object">
  <ParamField name="path" type="string" required>
    File path relative to repo root.
  </ParamField>
  <ParamField name="depth" type="number" optional defaultValue="3">
    Traversal depth for upstream/downstream (1–6).
  </ParamField>
</ParamField>

```json
{
  "file": "src/auth/guard.ts",
  "query_path": "src/auth/guard.ts",
  "found": true,
  "components": [
    { "name": "AuthGuard", "type": "guard", "line_number": 15 }
  ],
  "entrypoints": [
    {
      "name": "AuthGuard",
      "type": "guard",
      "guards": ["APP_GUARD"],
      "global_guards": ["AuthGuard"],
      "note": "Applied as global APP_GUARD"
    }
  ],
  "upstream": [
    { "name": "AppModule", "type": "module", "file_path": "src/app.module.ts" }
  ],
  "downstream": [
    { "name": "ClerkService", "type": "service", "file_path": "src/auth/clerk.service.ts" }
  ],
  "contracts": [],
  "global_guards": ["AuthGuard"],
  "depth": 3
}
```

**Guard detection rules:**
- NestJS: reads `@UseGuards()` decorators and `APP_GUARD` provider registration
- Next.js: detects `auth()` / `currentUser()` from `@clerk/nextjs/server`
- Entrypoints with no guards are flagged: `"[no auth detected — verify]"`
- `global_guards` lists all `APP_GUARD`-registered guards

Traversal uses recursive CTEs on `component_relations` for efficient graph walking.

## Impact Analysis (Blast Radius)

Determine what a change will affect:

```bash
curl -H "X-API-Key: drift_xxx" \
     "https://api.driftless.icu/api/v1/workspaces/my-team/repos/repo_uuid/graph/impact?files=src/auth/guard.ts,src/users/service.ts&depth=3&direction=consumers"
```

<ParamField query="query" type="object">
  <ParamField name="files" type="string" required>
    Comma-separated list of file paths.
  </ParamField>
  <ParamField name="depth" type="number" optional defaultValue="3">
    Traversal depth (1–6).
  </ParamField>
  <ParamField name="direction" type="string" optional defaultValue="both">
    `consumers` — upstream (what breaks if this changes)
    `dependencies` — downstream (what this depends on)
    `both` — bidirectional analysis
  </ParamField>
</ParamField>

```json
{
  "files": ["src/auth/guard.ts", "src/users/service.ts"],
  "found": 2,
  "direction": "consumers",
  "impacted_consumers": [
    { "name": "UserController", "file_path": "src/users/user.controller.ts", "distance": 1 }
  ],
  "impacted_entrypoints": [
    { "name": "GET /api/users", "file_path": "src/users/user.controller.ts", "guards": ["AuthGuard"] }
  ],
  "impacted_files": ["src/users/user.controller.ts", "src/users/user.module.ts"],
  "depends_on": [
    { "name": "ClerkService", "file_path": "src/auth/clerk.service.ts" }
  ],
  "global_guards": ["AuthGuard"],
  "depth": 3
}
```

## Context Load (Agent)

The primary endpoint for agents loading context before editing code:

```bash
curl -X POST https://api.driftless.icu/api/v1/workspaces/my-team/repos/repo_uuid/context/load \
  -H "X-API-Key: drift_xxx" \
  -H "Content-Type: application/json" \
  -d '{ "files": ["src/auth/guard.ts", "src/users/service.ts"] }'
```

<ParamField query="body" type="object">
  <ParamField name="files" type="string[]" required>
    Array of file paths to load context for.
  </ParamField>
</ParamField>

```json
{
  "files": [
    {
      "file": "src/auth/guard.ts",
      "found": true,
      "topics": {
        "direct": [
          { "slug": "auth-guard", "name": "Auth Guard", "kind": "code-context", "stale": false }
        ],
        "indirect": [
          { "slug": "b2b-routing", "name": "B2B Routing", "match_reason": "file_pattern" }
        ]
      },
      "graph_facts": {
        "entrypoints": [{ "name": "AuthGuard", "type": "guard" }],
        "upstream": [{ "name": "AppModule", "file_path": "src/app.module.ts" }],
        "downstream": [{ "name": "ClerkService", "file_path": "src/auth/clerk.service.ts" }],
        "contracts": [],
        "global_guards": ["AuthGuard"]
      },
      "coverage": {
        "status": "covered",
        "high_risk": false,
        "recommended_action": "none",
        "best_status": "reviewed",
        "match_specificity": 1.0,
        "has_stale": false,
        "has_orphaned": false
      }
    },
    {
      "file": "src/users/service.ts",
      "found": true,
      "topics": { "direct": [], "indirect": [] },
      "graph_facts": { "entrypoints": [], "upstream": [], "downstream": [], "contracts": [], "global_guards": [] },
      "coverage": {
        "status": "critical-gap",
        "high_risk": true,
        "recommended_action": "document-now",
        "best_status": "gap",
        "match_specificity": 0.0,
        "has_stale": false,
        "has_orphaned": false
      }
    }
  ]
}
```

### Coverage Statuses

| Status | Meaning |
| --- | --- |
| `covered` | File is fully covered by a reviewed topic |
| `partial` | File has some coverage but gaps remain |
| `gap` | File has no matching topics |
| `critical-gap` | File is a high-risk entrypoint with no coverage |
| `empty` | Repo has no topics at all |

### Recommended Actions

| Action | When |
| --- | --- |
| `document-now` | High-risk uncovered files (controllers, guards, routes) |
| `reattach-or-remove` | Orphaned topics still referencing this file |
| `refresh-stale` | Stale topics covering this file |
| `add-topic` | File with no topics, needs documentation |
| `review-suggested` | Suggested (AI-proposed) topics to review |
| `promote-draft` | Draft topics to publish |
| `none` | File is adequately covered |

**Topic matching** works in two layers:
1. **Direct** — topic's `where_files` or `components` explicitly reference the file
2. **Indirect** — topic's `patterns` glob match the file path
