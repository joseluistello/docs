Driftless supports two authentication paths: API Keys for CLI and programmatic access, and Clerk for browser-based dashboard access.

## API Keys (CLI + Programmatic)

API keys use the `X-API-Key` header and start with the `drift_` prefix.

### Creating Keys

Create API keys via the [Dashboard](https://driftless.icu) Settings page or via the API:

```bash
curl -X POST https://api.driftless.icu/api/v1/auth/api-keys \
  -H "Authorization: Bearer <clerk_token>" \
  -H "Content-Type: application/json" \
  -d '{ "name": "my-cli-key" }'
```

```json
{
  "key": "drift_abc123def456...",
  "prefix": "drift_abc",
  "id": "key_uuid_here"
}
```

**Important:** The raw key is shown only once at creation. Keys are stored as SHA-256 hashes — the server cannot recover a lost key.

### Using API Keys

```bash
curl -H "X-API-Key: drift_xxx" https://api.driftless.icu/api/v1/me
```

Validate a key by calling the `/me` endpoint. A `200` response confirms the key is valid and returns the associated workspace.

### Managing API Keys

<Accordion title="List API Keys">
  ```bash
  curl -H "Authorization: Bearer <clerk_token>" \
       https://api.driftless.icu/api/v1/auth/api-keys
  ```
  Only key prefixes and IDs are returned — never the raw key.
</Accordion>

<Accordion title="Revoke an API Key">
  ```bash
  curl -X DELETE \
       -H "Authorization: Bearer <clerk_token>" \
       https://api.driftless.icu/api/v1/auth/api-keys/key_uuid_here
  ```
</Accordion>

## Clerk (Dashboard / Browser)

For browser-based access, use a Clerk Bearer token:

```
Authorization: Bearer <clerk_token>
```

Obtain the token via Clerk's `getToken()` method in the browser. The user must be a member of a Clerk organization. On first access, if the Clerk org matches a workspace slug, the workspace is auto-created.

## Rate Limiting

| Tier | Limit |
| --- | --- |
| Authenticated (API key or Clerk) | 200 req/min |
| Public endpoints | 30 req/min |
| Webhooks | 50–100 req/min |
