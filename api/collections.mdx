title: 'Collections, contact Records & Entities'
description: 'REST endpoints for the contact-first CRM substrate behind Prospectos.'
---

All paths are under `/api/v1` and require authentication. The customer-facing CRM use is contact-first: a Collection holds people the workspace explicitly acquired and filed. A company, market row, or evidence item does not become a Record merely because a generic Record endpoint exists.

## Collections

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/workspaces/:slug/collections` | Create a configured, contact-oriented Collection. |
| `GET` | `/workspaces/:slug/collections` | List active Collections, bounded. |
| `GET` | `/workspaces/:slug/collections/search` | Search Collections by intent. |
| `GET` | `/workspaces/:slug/collections/:id` | Read one Collection, with explicit `view=brief|full`. |
| `PATCH` | `/workspaces/:slug/collections/:id` | Update safe configuration. Lifecycle changes use explicit routes. |
| `POST` | `/workspaces/:slug/collections/:id/archive` | Reversibly retire a Collection. |
| `POST` | `/workspaces/:slug/collections/:id/restore` | Restore an archived Collection. |
| `DELETE` | `/workspaces/:slug/collections/:id` | Permanent owner/admin purge after dry-run/version checks. |

The server owns the contact shape and lifecycle validation. Do not use a generic collection configuration path to turn a company, supplier observation, tender, award, permit, or research result into a CRM contact.

## Contact Records

Base path: `/workspaces/:slug/collections/:id/records`.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `.../records` | Create a Record only through the authorized contact-filing path. |
| `GET` | `.../records` | Bounded, active-only Record page. |
| `GET` | `.../records/:recordId` | Read one contact Record. |
| `PATCH` | `.../records/:recordId` | Update an existing contact Record and its status. |
| `DELETE` | `.../records/:recordId` | Explicit governed deletion; never a bulk extraction path. |

A current customer flow normally reaches Record creation through the Radar/people contact path: search, quote the selected people, explicitly confirm, reveal/import, then file the chosen contact. A generic REST Record write must not be used to bypass that selection and authorization contract.

Record statuses are validated against the Collection's configured stages. `entity_id` is a top-level compatibility property, not a way to attach an unverified company to a person.

## Entities

Entity routes remain available for active technical consumers and shared identity resolution. They are not a public MCP tool and do not prove that an approximate name or client-supplied URL is a company identity.

## Pagination and errors

Collection and Record reads use bounded pages and opaque cursors. Follow `nextCursor` before concluding coverage. Invalid fields, statuses, or filters return the current [error envelope](/api/errors).

## Lifecycle

`archive` and `restore` are separate reversible operations. `purge` is permanent, owner/admin only, audited, and should be previewed with its current dry-run/version contract. A status update never silently performs archive or purge.
