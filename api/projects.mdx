title: 'Projects & Cards'
description: 'REST endpoints for project boards and the card loop. Reads are active-only and brief by default; close, archive, restore and purge are explicit, governed lifecycle routes.'
---

All paths are under the base URL (`/api/v1`) and require authentication (an API key or a dashboard session). Reads are workspace-member; writes require the `work:write` scope over OAuth; **purge is owner/admin only**. Reads are **active-only, bounded and brief by default** — archived objects only surface with an explicit opt-in. See [Projects](/concepts/projects) for the model.

## Projects

| Method | Path | Perm | Purpose |
|---|---|---|---|
| `POST` | `/workspaces/:slug/projects` | member (`work:write`) | Create a project |
| `GET` | `/workspaces/:slug/projects` | member | List projects (`?status=&owner=&updated_after=&limit=&cursor=`). Default `active`; bare array, or `{items, shown, has_more, nextCursor}` when any paging param is present |
| `GET` | `/workspaces/:slug/projects/search` | member | Intent-ranked search (`?q=&status=&include_archived=&owner=&updated_after=&limit=&cursor=`). `q` required; `items[]` carry `score`; active-only unless `include_archived=true` |
| `GET` | `/workspaces/:slug/projects/:id` | member | Project detail (`?view=summary\|brief\|full`, `card_limit`, `card_offset`, `card_status`). **Brief by default**; `full` is explicit |
| `PATCH` | `/workspaces/:slug/projects/:id` | member (`work:write`) | Update metadata. Rejects `status` touching lifecycle (`409`) — use close/archive/restore |
| `POST` | `/workspaces/:slug/projects/:id/close` | member (`work:write`) | Validate completion and distill write-back Notes; returns `{project, context_outcome}` (idempotent) |
| `POST` | `/workspaces/:slug/projects/:id/archive` | member (`work:write`) | Reversibly retire a `done` project; `version += 1`; archived is immutable |
| `POST` | `/workspaces/:slug/projects/:id/restore` | member (`work:write`) | Restore an archived project to `done` |
| `DELETE` | `/workspaces/:slug/projects/:id` | owner/admin | Purge an archived project (`?dry_run=&expected_version=`). CAS, audited, idempotent, preserves origin Notes |

Create body (`CreateProjectDto`): `title` (required), `goal`, `playbook_slug`, `owner_clerk_id`, `context[]`. Update accepts `title`, `goal`, `playbook_slug`, `owner_clerk_id`, `add_context` — a `status` of `done`/`archived` returns `409` and names the lifecycle route to use.

## Cards

Base path `/workspaces/:slug/projects/:projectId/cards`.

| Method | Path | Perm | Purpose |
|---|---|---|---|
| `POST` | `.../cards` | member (`work:write`) | Create a card |
| `GET` | `.../cards` | member | List cards (`?status=&limit=&owner=&offset=`). Bounded; `offset` paging; ordered by planning priority |
| `GET` | `.../cards/next` | member | The loop tick (`?context=refs\|summaries\|full`); returns a card plus its context bundle, or a terminal signal |
| `GET` | `.../cards/:cardId` | member | Card detail (includes `origin_notes`) |
| `PATCH` | `.../cards/:cardId` | member (`work:write`) | Update a card (or move with `to_project_id`) |
| `DELETE` | `.../cards/:cardId` | member (`work:write`) | Safe delete a `todo` card (`?dry_run=`). Rejects dependents and origin Notes; idempotent |

Create body (`CreateCardDto`): `title` (required), `description`, `status`, `owner_clerk_id`, `acceptance`, `validate`, `depends_on` (uuid array), `context`, `allow_secrets`. Update also accepts `to_project_id`, `validate_result`, `validate_passed` and `add_context`.

```bash
curl -X POST https://api.driftless.icu/api/v1/workspaces/acme/projects \
  -H "x-api-key: drift_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{"title":"Refunds revamp","goal":"Refund path is idempotent","playbook_slug":"refund-flow"}'
```

## Bodies, pagination, and errors

Project `list` and `search` paginate by **keyset cursor** (`limit` 1–50, default 20; `cursor` opaque from the prior `nextCursor`). Embed of cards inside `GET /:id` paginates by `card_offset`/`card_limit` (offset paging) and is bounded by `card_status`. `next` returns a card plus its context bundle, or a terminal signal when nothing is actionable. A `context_outcome` from `close` is `{ status, retryable, topic?, reason? }` with `status` one of `created` · `already_exists` · `skipped` · `failed`. Purge `impact` is `{ project_id, version, cards, context_refs, origin_notes_preserved }`; card delete `impact` is `{ card_id, dependents, origin_notes, context_refs }`. Status values are validated against the card enum (`todo`, `in_progress`, `blocked`, `review`, `done`) and the project enum (`active`, `done`, `archived`); an invalid value returns `400 VALIDATION_FAILED`. Unknown body fields are rejected. See [errors](/api/errors) for the envelope.

## Lifecycle: close, archive and purge

- **`POST .../:id/close`** validates completion (no remaining `todo`/`in_progress`/`blocked`/`review` cards), distills the project's write-back Notes into a draft Topic **once**, and stores `close_context_outcome`. Body `{no_durable_learning?: true}`. Idempotent — a repeat returns `already_exists` and never re-distills. Rejects `--no-durable-learning` when durable Notes exist (`400`); refuses to run against an archived project (`409`).
- **`POST .../:id/archive`** retires a `done` project to `archived`. **`POST .../:id/restore`** revives an `archived` project to `done`. Both increment `version` and are audited. An archived project is **immutable** — `PATCH`, `close` and card writes return `409 PROTECTED_RESOURCE`.
- **`DELETE .../:id?dry_run=true`** previews impact (`origin_notes_preserved` counts the write-back Notes that **survive** the delete). **`DELETE .../:id?expected_version=<n>`** performs the purge with compare-and-set; a mismatched `expected_version` returns `409 VERSION_CONFLICT`. **Owner/admin only**, audited, idempotent — a repeat after the purge returns `already_absent`.

The safe **card delete** is the same shape: `DELETE .../cards/:cardId` only deletes a `todo` card, **rejects** cards that other cards depend on (`409`, lists dependents), and **rejects** cards with origin write-back Notes (`409`). `?dry_run=true` previews the blockers. A repeat after the delete returns `already_absent`.
