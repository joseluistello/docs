title: 'Workspace and team administration'
description: 'Manage Brein workspace details, members, roles, scoped API keys, billing, and deletion.'
---

All routes are workspace-scoped and authenticated. A caller must have live membership in the workspace named by the URL; a non-member does not receive another tenant's data.

## Workspace lifecycle

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/workspaces` | Bootstrap a workspace during first-run enrollment. |
| `GET` | `/workspaces/self-serve` | Read the public/self-serve bootstrap contract where enabled. |
| `GET` | `/workspaces/:slug` | Read workspace details. |
| `PATCH` | `/workspaces/:slug` | Update ordinary workspace settings. |
| `PATCH` | `/workspaces/:slug/plan` | Apply a server-owned plan change where allowed. |
| `DELETE` | `/workspaces/:slug` | Delete the workspace under the current human and confirmation contract. |

Plan and billing changes are server-owned. A client cannot author its own Stripe price or allowance metadata.

## Members and roles

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/workspaces/:slug/members` | List members and roles. |
| `POST` | `/workspaces/:slug/members` | Invite a member. |
| `PATCH` | `/workspaces/:slug/members/:memberId` | Change an eligible role. |
| `DELETE` | `/workspaces/:slug/members/:memberId` | Remove a member. |

Roles are `owner`, `admin`, and `member`. Owner transfer and last-owner protections are enforced server-side. Removing membership revokes the person's live access to the workspace.

## Scoped API keys

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/workspaces/:slug/api-keys` | List key metadata, never raw secrets. |
| `POST` | `/workspaces/:slug/api-keys` | Create a scoped key. |
| `DELETE` | `/workspaces/:slug/api-keys/:id` | Revoke a key. |

The raw key is shown only once. A key can be authorized for multiple workspaces, but its live access never exceeds its human identity's current membership and role.

## Commercial usage

`GET /workspaces/:slug/commercial-usage` returns the server-authoritative plan, request usage, intelligence credits, separate contact credits, renewal date, promotional availability, and the correct next action. Do not infer allowance from client state.

## Errors and safety

Use the stable error envelope and branch on `code`, not prose. Member, key, billing, and deletion operations are audited. Secrets are never returned in list responses, error messages, logs, or docs.
