## `driftless graph file`

Inspect a file's position in the code graph: entrypoints, dependencies, consumers, and guards.

```bash
driftless graph file src/auth/guard.ts
driftless graph file src/auth/guard.ts --depth 2 --json
```

| Flag | Description |
|---|---|
| `<path>` | File to inspect (required) |
| `--depth N` | Traversal depth, 1–6 (default: 3) |
| `--json` | Machine-readable output |

**Output includes:**

- **Entrypoints** — HTTP methods and paths (e.g., `GET /api/users`, `POST /api/users`)
- **Upstream dependencies** — files this file imports
- **Downstream consumers** — files that import this file
- **Contracts** — interfaces, types, and exports this file provides
- **Guards** — auth guards on entrypoints; global guards shown if `APP_GUARD` is set

<Warning>
  If an entrypoint has no guards, the output prints `[no auth detected — verify]`. Driftless never assumes a route is public. Composed decorators and indirect guard application can cause false positives — always verify.
</Warning>

## `driftless graph impact`

Determine the blast radius of a change. What breaks if these files are modified?

```bash
driftless graph impact --files "src/shared/utils.ts"
driftless graph impact --files "src/auth/service.ts,src/auth/guard.ts" --direction both
```

| Flag | Description |
|---|---|
| `--files "a,b"` | Comma-separated file paths (required) |
| `--depth N` | Traversal depth, 1–6 (default: 3) |
| `--direction <upstream\|downstream\|both>` | Impact direction (default: `upstream`) |
| `--json` | Machine-readable output |

**Output includes:**

- **Impacted consumers** — files that depend on the changed files
- **Impacted entrypoints** — HTTP routes affected by the change
- **Impacted files** — full set of files reachable from the change
- **Depends on** — what the changed files themselves depend on

<Note>
  `--direction upstream` answers "what will my change break?" — the most common question before a PR. `--direction downstream` answers "what am I about to break?" and is useful for shared utility changes.
</Note>

## `driftless graph coverage`

Overview of context coverage across the codebase.

```bash
driftless graph coverage
driftless graph coverage --json
```

Fetches an architecture summary from the API and shows per-module coverage, count of high-risk uncovered components, and stale/orphaned topic counts.
