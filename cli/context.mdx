## `driftless context list`

List all context topics with optional filters.

```bash
driftless context list
driftless context list --stale --auto
driftless context list --status reviewed --kind code-context
```

| Flag | Description |
|---|---|
| `--stale` | Show only stale topics |
| `--docs` | Show only topics with anchored docs |
| `--auto` | Auto-scope to current repo (avoids orphaned topics) |
| `--manual` | Show only manually created topics |
| `--suggested` | Include suggested/draft topics (hidden by default) |
| `--status <value>` | Filter by status (`reviewed`, `draft`, `orphaned`) |
| `--kind <value>` | Filter by kind (`code-context`, `domain-map`, `decision`, etc.) |
| `--repo <id>` | Filter by repo ID |
| `--json` | Machine-readable output |

<Tip>
  Use `--auto` to automatically scope results to the current repo. Without it, you may see orphaned topics from other repos.
</Tip>

## `driftless context get`

Retrieve full detail for a single topic, or match topics to files/changes.

```bash
# Single topic
driftless context get b2b-guard
driftless context get b2b-guard --json

# Match topics to specific files
driftless context get --files "src/auth/guard.ts,src/auth/service.ts"

# Topics for current local changes
driftless context get --diff
```

Shows: `what`, `how`, `decisions`, `gotchas`, `content`, `tags`, wiki-links, anchors, components, invariants, relations, history, and stale status.

`--diff` runs `git diff --name-only HEAD` plus staged changes. If no local changes are detected, the CLI prints `No local changes detected.`

## `driftless context add`

Create a new context topic.

```bash
driftless context add "payment-flow" \
  --what "Stripe checkout and webhook handling" \
  --how "Stripe SDK in billing module, idempotency via DB" \
  --decisions "Replay-safe webhooks chosen over queue" \
  --gotchas "Idempotency keys required for all mutations" \
  --pattern "src/billing/**" \
  --pattern "src/webhooks/stripe/**" \
  --kind code-context \
  --tags billing,payment,webhooks \
  --rel depends_on:email-service
```

| Flag | Description |
|---|---|
| `--what "<text>"` | What this topic covers |
| `--how "<text>"` | How it is implemented |
| `--decisions "<text>"` | Why certain patterns were chosen |
| `--gotchas "<text>"` | Known traps / gotchas |
| `--ownership "<text>"` | Who owns this topic |
| `--content "<text>"` or `--content @path/to/file.md` | Markdown body |
| `--file <path>` | Anchor a doc file to the topic |
| `--pattern "glob"` | File anchor glob (repeatable; 0 matches = rejected) |
| `--tags tag1,tag2` | Comma-separated tags |
| `--status <reviewed\|draft\|orphaned>` | Topic status |
| `--kind <code-context\|domain-map\|decision\|roadmap\|runbook\|customer-insight\|integration-note\|docs-note\|operational-note>` | Topic kind |
| `--rel <type>:<slug>` | Typed relation (repeatable) |
| `--dry-run` | Validate without creating |
| `--json` | Machine-readable output |

**Relation types:** `depends_on:`, `relates_to:`, `supersedes:`, `blocks:`, `implements:`, `documents:`, `risk_for:`

<Warning>
  Anchoring a topic to more than 100 components emits a non-blocking warning. Keep topics narrow (5–40 components is healthy).
</Warning>

## `driftless context update`

Modify an existing topic. Every update bumps the version and writes history.

```bash
driftless context update payment-flow \
  --gotcha "Idempotency keys required for all mutations" \
  --decision "Migrated to Stripe v2 SDK" \
  --invariant "Every checkout must have a customer_id" \
  --add-pattern "src/webhooks/stripe/**" \
  --rel depends_on:refund-flow
```

| Flag | Description |
|---|---|
| `--what`, `--how`, `--decisions`, `--gotchas`, `--ownership`, `--status`, `--kind`, `--content`, `--tags` | Scalar replace (full replace) |
| `--gotcha "<text>"` | Append a gotcha (history-preserving, repeatable) |
| `--decision "<text>"` | Append a decision (history-preserving, repeatable) |
| `--invariant "<text>"` | Append an invariant (history-preserving, repeatable) |
| `--check "<text>"` | Append a check (history-preserving, repeatable) |
| `--pattern "<glob>"` | Replace all anchors (use with caution) |
| `--add-pattern "<glob>"` | Append anchor (idempotent) |
| `--remove-pattern "<glob>"` | Remove anchor (idempotent) |
| `--rel <type>:<slug>` | Add a typed relation |
| `--dry-run` | Validate without applying |
| `--json` | Machine-readable output |

<Note>
  **Cross-repo linkage is automatic.** Every `context update` call auto-attaches the current repo to the topic's `where_repos` field. Run `context update` from each repo that shares the topic to build cross-repo context.
</Note>

## `driftless context load`

Load context + coverage for specific files in a single call.

```bash
driftless context load --files "src/auth/guard.ts,src/auth/service.ts"
```

Returns per-file: matching topics (direct and indirect), graph facts (entrypoints, guards, upstream/downstream), coverage status, and a recommended action.

| Flag | Description |
|---|---|
| `--files "a,b"` | Comma-separated file paths |
| `--dry-run` | Validate without loading |
| `--json` | Machine-readable output |

## `driftless context sync`

Anchor a doc or add a note to a topic.

```bash
# Anchor a markdown doc
driftless context sync payment-flow --doc docs/billing.md

# Add a note as a decision
driftless context sync payment-flow --note "Stripe webhook secret rotated Q2 2026"
```

| Flag | Description |
|---|---|
| `--doc <path>` | Local doc file to anchor (sets `file_content`, `anchored_doc_path`, origin `doc`, status `draft`, kind `docs-note`) |
| `--note "..."` | Note to add as a decision |
| `--files "a,b"` | Optional file anchors for the note |
| `--pattern "glob"` | Optional pattern anchor for the note |

## `driftless context doctor`

Audit context health across the workspace.

```bash
driftless context doctor
```

Reports: stale topics, orphaned topics, draft topics, docs-pending topics, and repo-leak topics (topics attached to repos no longer present). Exits with code `1` if orphaned or repo-leak topics exist.

## `driftless context relations`

List typed relations for a topic, both outgoing and incoming.

```bash
driftless context relations payment-flow --json
```

## `driftless context graph`

```bash

driftless context graph payment-flow --depth 2 --json
```

| Flag | Description |
|---|---|
| `--depth N` | BFS depth (default: 3) |
| `--json` | Machine-readable output |
