Brein can support a software team's engineering context through Cerebro documents and path anchors. This is a secondary use case, separate from the commercial customer journey.

## The engineering loop

1. **Retrieve before editing.** Use the CLI or current MCP tools:

   ```bash
   driftless context get --files "src/auth/guard.ts,src/auth/service.ts"
   driftless context get <document>
   ```

   Over MCP, start with `context_retrieve` and then call `context_get` for the one full document you need. Read the durable why — decisions, gotchas, invariants, and freshness — before changing code.

2. **Create or rewrite one clean document.** If no document covers the area, create one with `driftless context add` or `context_create`. If one exists, read it and consolidate the new fact with `context write` or `context_update`. A document is born shared with the workspace; there is no Note → Knowledge approval queue.

3. **Use anchors narrowly.** A code document may point to a small, explicit set of paths or globs. An over-broad or zero-match anchor is a signal to fix the document, not to claim the code is covered.

4. **Persist only durable knowledge.** Do not turn a command transcript, temporary task, or one-off value into a document. The durable question is whether a future change would meaningfully contradict the claim.

5. **Reconnect after schema changes.** MCP clients cache tool definitions per connector session. Start a fresh session or reconnect the connector after Brein changes a schema.

## Installed files

```bash
pnpm add -g @driftless-sh/cli
# or
npm install -g @driftless-sh/cli
driftless login
driftless install-skill
```

`install-skill` writes the managed `AGENTS.md` and `CLAUDE.md` blocks plus `.driftless/skill.md` for supported coding agents. Re-run it after upgrading the CLI when you want the installed instructions refreshed.

## Read the current MCP surface

Use neutral capability names such as `context_retrieve`, `context_get`, `context_ls`, `context_read`, `context_write`, `context_search`, `collection_query`, `crm_record`, `people_file`, and `sequence_activate`.

Do not build a new integration around retired tools such as `driftless_context_search`, `driftless_context_create`, `driftless_collection`, `driftless_tags`, or `driftless_areas`. Hidden aliases exist only for the documented compatibility window; they are not the current catalog.

## Commercial safety

The engineering skill does not grant permission to reveal contacts, spend credits, send email, or make consequential CRM decisions. Those operations have their own server-side scopes, explicit selections, confirmations, and audit requirements. See [MCP: Sequences](/mcp/sequences) and [The Brein workspace](/product/workspace).
