title: 'MCP: Integrations'
description: 'Read data from a ready, already-connected provider through synthesized provider-specific MCP tools.'
---

External systems are reached over MCP through **synthesized connector tools**. A ready provider connection may expose:

- `<provider>_records` — a bounded, delta-aware page from a synced model;
- `<provider>_document_content` — bounded, citeable content from a document provider.

These tools operate on a Connection that already exists. They do not connect or disconnect a provider; setup remains a human-led flow in the dashboard or CLI. If the required capability is not listed, report the missing capability rather than authoring a script.

There is no generic `broker` MCP router. A legacy `driftless_broker` call answers `Unknown tool`. The Broker remains available through its CLI and REST surfaces.

## Synthesized tools

| Tool | Effect | Boundary |
|---|---|---|
| `<provider>_records` | read | Synced provider data; bounded page and cursor. |
| `<provider>_document_content` | read | Live or materialized document content according to the provider capability. |

A tool appears only when synthesis is enabled, the provider exposes a `ready` read capability, and the workspace rollout permits it. A listed tool still requires the normal connection, grant, and workspace authorization checks.

## Gates and permissions

The Broker and synthesized tools are fail-closed. The feature switch, external rollout, per-principal grant, operation policy, connection health, and workspace scope must all allow the read. A listed tool is not automatically usable.

Write capabilities are never synthesized. Connecting a provider, deploying a connector function, or managing grants is outside this MCP read surface.
