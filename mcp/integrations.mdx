External systems are reached over MCP through **synthesized connector tools**: a ready
provider connection exposes `<provider>_records` and
`<provider>_document_content` in `tools/list`. They operate a [Connection](/integrations/overview) that already exists, and never connect or disconnect one (setup is a human-led flow in the dashboard or CLI, not on the MCP surface). If an agent needs data the tool does not expose, it must report the missing capability, never author a script.

The generic `broker` router (the action-based `connections` / `operations` / `invoke` / `records` / `index` tool) has **no MCP tool at all**: its definition and handler were deleted, not merely hidden — a legacy `driftless_broker` call now answers "Unknown tool". It remains available through the CLI and dashboard.

<Warning>
The Broker is **gated**: off by default in production (`DRIFTLESS_BROKER_ENABLED`), with a separate external lane (`DRIFTLESS_BROKER_ROLLOUT`) and per-principal grants. A listed tool is not a usable one: a faceless OAuth/MCP caller with no grant gets an empty result even against a healthy connection.
</Warning>

## Synthesized connector tools

| Tool | Purpose | Effect |
| --- | --- | --- |
| `<provider>_records` | Read a synced model's records from the mirror (bounded page, delta-aware) | read |
| `<provider>_document_content` | Read one document's bounded, citeable text, live (any content provider) | read |

```text
notion_records model:'ContentMetadata' limit:5
notion_document_content external_id:'<id>'
```

## Gates and permissions

Three independent, fail-closed gates apply to an external caller, in order: the master switch (`DRIFTLESS_BROKER_ENABLED`), the external lane (`DRIFTLESS_BROKER_ROLLOUT`), and a per-principal grant. An operation must also be policy-allowed; in production the policy registry ships empty, so no write is invokable.

| Scope | Covers |
| --- | --- |
| `broker:read` | Connector reads (`records`, `document-content`) |
| `broker:invoke` / `broker:admin` | The generic broker router's write/admin actions (deleted from the MCP catalog; CLI/dashboard only) |

The `broker:*` scopes are enforced only when the Broker is enabled, and they gate the lane on top of rollout and grants. An internal caller (an owned API key or dashboard session) skips the grant gate but still needs the rest.

## Availability

| Capability | State |
| --- | --- |
| Synthesized per-workspace read tools (`<provider>_records`, `<provider>_document_content`) | Available only when synthesis is enabled and a capability is `ready` |
| Write-capability synthesis | Not available (never synthesized) |
| Generic `broker` router in `tools/list` | Deleted — no MCP tool at all |
