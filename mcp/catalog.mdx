These are the **49** public MCP tools. The server's `tools/list` response is the canonical schema; if this page and the schema differ, the schema wins.

All accept `workspace` (optional). **Yes** in the last column means a person must confirm. **Credits** means it can spend them.

## Cerebro

| Tool | What it does | Yes |
|---|---|---|
| `context_read` | Searches (`query`), opens (`path`) or browses Cerebro folders. | No |
| `context_write` | Creates a new document; refuses a path that already exists. | No |
| `context_propose_rewrite` | Step 1: seals the full new text against the version read. | No |
| `context_rewrite` | Step 2: writes what was sealed. | Yes |

## Companies, contacts and pipelines

| Tool | What it does | Yes |
|---|---|---|
| `crm_read` | Every read of what is yours, by `object`: `company`, `contact`, `list`, `opportunity`, `product`. | No |
| `crm_collection` | Creates a pipeline with the stages named. | No |
| `crm_propose_create` | Proposes a new opportunity and returns an `update_token`. | No |
| `crm_create_opportunity` | Creates the approved opportunity. | Yes |
| `crm_propose_update` | Proposes a change to an opportunity. | No |
| `crm_update_opportunity` | Applies the approved change. | Yes |
| `crm_propose_import` | Validates 1 to 1000 rows without writing. | No |
| `crm_import_opportunities` | Applies the approved import. | Yes |
| `crm_schedule_activity` | Schedules a follow-up. Sends nothing and moves nothing. | No |
| `crm_group_propose` | Step 1 on a group: file in a pipeline, change stage, archive or unarchive. Counts the group and changes nothing. | No |
| `crm_group_apply` | Step 2. Up to 50 is applied; more than 50 or a stage change needs `confirm`. | Depends |
| `contact_update` | Notes a fact, corrects email, phone or LinkedIn, or archives. | No |
| `contact_file` | Files an already revealed or imported person in a pipeline. | No |

## Market and web

Read-only. They return bounded results with their source and never contact details.

| Tool | What it does | Yes |
|---|---|---|
| `market_resolve` | Sees what exists for a name or topic: buyers, sellers and companies with counts. | No |
| `market_aggregate` | Totals computed on the server across up to three dimensions. | No |
| `market_search_companies` | Searches the directory and the importers and exporters registry. | No |
| `market_search_records` | Searches tenders, awards, permits and risks by `kind`. | No |
| `market_get` | Opens a row by its `ref`. | No |
| `market_screen_risks` | Checks up to 50 RFCs against risk lists. | No |
| `web_search` | A snapshot of public sources. Saves nothing. | No |

Start with `market_resolve`, continue with `market_aggregate` and read rows only when the question is precise. A guessed filter returns zero rows with no meaning: filter by values a tool showed you.

## Sequences

A draft is inert.

| Tool | What it does | Yes |
|---|---|---|
| `sequence_read` | Every read by `view`: `list`, `detail`, `preview`, `metrics`, `analytics`, `mailboxes`. | No |
| `sequence_create_draft` | Creates a draft. | No |
| `sequence_edit` | Edits the draft and its steps. | No |
| `sequence_check` | Checks whether it is ready and returns an activation token. | No |
| `sequence_activate` | Starts real sending. | Yes · sends email |
| `sequence_pause` | Stops the next sends. | No |
| `sequence_cancel` | Stops the pending ones for good. | No |
| `sequence_propose_reply` | Seals a reply written by a person. | No |
| `sequence_reply_thread` | Sends the sealed reply. | Yes · sends email |

## How to use the catalog

1. Start with a read.
2. Confirm the workspace and the audience.
3. Run the quote, the preview or the check.
4. Call the tool that writes or activates only after the person confirms.
