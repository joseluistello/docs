title: 'MCP: Sequences'
description: 'Prepare, review, explicitly authorize, activate, pause, and measure bounded outbound email sequences through governed MCP tools.'

MCP exposes the campaign lifecycle, but it does not turn sending into an implicit side effect. A sequence starts as an inert draft. Before real email leaves the workspace, the person must see the audience, steps, readiness result, and warnings, then explicitly confirm activation with the server-issued proof.

Brein observes engagement with its own outbound messages — opens, clicks, and the existence of a reply — without reading the customer's inbox. Replies remain in Gmail or Outlook.

## Tools

| Tool | Purpose |
| --- | --- |
| `sequence_list` | List sequences in the workspace with status and sender context. |
| `sequence_get` | Read the sequence, steps, masked recipients, rendered messages, sender, and authorization history. |
| `sequence_create_draft` | Create an inert draft from acquired contacts or an explicitly valid audience. |
| `sequence_update_draft` | Edit an unsent draft. |
| `sequence_preview` | Render the messages as they would send, with personalization and suppressions applied. |
| `sequence_check` | Run preflight and return `blocking`, `warnings`, and `ready`. |
| `sequence_activate` | Activate a ready sequence after a human confirms the reviewed audience and proof. |
| `sequence_pause` | Stop further sends while preserving the draft and history. |
| `sequence_cancel` | End the sequence and stop pending recipients without deleting history. |
| `sequence_metrics` | Read per-sequence people-level outcomes. |
| `sequence_analytics` | Read workspace-level campaign and engagement analytics. |
| `sequence_reply_thread` | Read reply metadata and thread identity, never the customer's message body. |
| `mailbox_status` | Read sender health and capacity without exposing mailbox addresses. |
| `mailbox_propose_pace` | Prepare a sealed pacing proposal. |
| `mailbox_set_pace` | Apply pacing only after the sealed proposal and explicit confirmation. |

## The activation boundary

A successful preflight is necessary but not sufficient. `sequence_activate` requires:

1. a ready sequence;
2. an activation token minted by `sequence_check`, valid for ten minutes and bound to that exact audience, step count, and sender;
3. `confirm: true` after a person has reviewed and agreed to the send.

There is no per-recipient send tool and no way to bypass the human authorization by calling a generic action router. A draft can be edited or checked as often as needed; creating it never confirms, schedules, or sends anything.

## Audience safety

Campaigns use acquired contacts whose work email is already available and whose rights permit contact. A company, market row, research observation, or masked person is not automatically a campaign recipient. If a selected contact is suppressed, the preflight reports it instead of quietly sending to someone else.

## What Brein observes

The outbound system can report that a message was opened, that a link was clicked, or that a reply exists on the thread. Those are engagement signals from the sending provider's tracking infrastructure. Brein does not import, index, search, summarize, or return inbox messages, threads, contacts, drafts, or message bodies.

Counts are people who engaged at least once, not raw tracking events. A click on a configured booking link is intent to follow up, not proof of a meeting and not permission to move a CRM Record automatically.
