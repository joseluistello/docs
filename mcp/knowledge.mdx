This is the Cerebro plane over MCP: the tools an AI client uses to read the team's commercial criterion before acting (offer, ICP, exclusions, signals, geography, buyers, messages, playbooks) and to maintain it. For setup, authentication, and the OAuth scopes referenced below, see [MCP & OAuth](/mcp/overview).

Public tools use neutral capability names without a product prefix. Their `brein_*` and `driftless_*` aliases resolve to the same tool but are not advertised in `tools/list`.

## Retrieval and reading

Start with `context_retrieve` when you have a task but no slug. Bodies come back **brief** by default (the durable why, not the full `content`); fetch one full body with `context_get`.

| Tool | Purpose | Main params | Returns |
| --- | --- | --- | --- |
| `context_retrieve` | Ranked context for a task and/or files — absorbs full-text search, listing and file-matching (MCP · 2) | `task`, `files`, `tags`, `area`, `stale`, `status`, `view`, `limit` | `{ shown, has_more, next_action, results[] }` |
| `context_get` | One topic by slug (full body) | `topic`, `view` | the full topic |

`context_search`, `context_list` and `context_get_for_files` no longer appear in `tools/list` — `context_retrieve` already took their arguments (`query`→`task`, `status`/`stale`/`tags`, `files`). They remain resolvable for 60 days as hidden compatibility aliases (their result names the replacement in `next_action`); after that window they answer "Unknown tool".

Permission: `context:read`. Availability: Available.

```text
context_retrieve task:'harden the webhook handler' files:['src/webhooks/handler.ts']
  → { results: [ { slug, trust, why_matched, confidence } ], has_more }
```

## Writing and editing

| Tool | Purpose | Main params | Notes |
| --- | --- | --- | --- |
| `context_create` | Create a criterion document | `title`, `content`, `area` | the document is born shared with the workspace — there is no review queue anywhere (MCP · 2) |
| `context_update` | Append-safe update | `topic`, fields | returns `anchor_validation` |

Permissions: `topics:create` / `topics:write`. Availability: Available. Write responses carry `anchor_validation` (`ok` / `overbroad` / `zero`), which never blocks the write. No agent tool deletes a topic or publishes a public page — see below.

## Deleted from the catalog

The following surfaces have no MCP tool at all — their definitions and handlers
were removed, not merely hidden; a legacy `driftless_*` call now answers
"Unknown tool". Their curation remains available to owners through the CLI and
dashboard:

- Notes as a standalone product (`note_add`);
- topic graph (`context_graph`) and relations (`context_relations`);
- comments (`context_comment`);
- the retired Note→Knowledge governance (`context_propose`, `_approve`,
  `_create_proposal`, `_proposals`, `_merge`) — there is nothing to approve;
- events and doctor (`context_events`, `_doctor`);
- areas and tags (`areas`, `tags`);
- delete (`context_delete`) — no agent tool deletes a topic;
- publish to the web (`context_share`) — publishing is human work, not an agent action.

## Permissions

| Scope | Covers |
| --- | --- |
| `context:read` | Read topics, retrieve, search, list |
| `topics:create` | Create topics |
| `topics:write` | Update existing topics |
| `context:diff` | Read topic diff for local changes |
