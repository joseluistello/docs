Driftless gives your team — and your AI agents — a shared, always-fresh layer of context about your codebase. You define topics (what a module does, how it works, known gotchas, decisions), Driftless watches your PRs and pushes, and automatically flags topics that have drifted from the code they describe.

## How it works

<Steps>
  <Step title="Install and authenticate">
    Install the CLI globally and log in with your API key.
    ```bash
    npm install -g @driftless-sh/cli
    driftless login
    ```
  </Step>
  <Step title="Initialize your repo">
    Run `driftless init` to scan your repo, upload structural metadata, and install the AGENTS.md skill.
    ```bash
    driftless init
    ```
  </Step>
  <Step title="Add context topics">
    Create topics that describe key modules, decisions, and gotchas. Topics can cover files via glob patterns.
    ```bash
    driftless context add "auth-boundaries" \
      --content "# Auth\n\n## What\nHandles JWT validation and org-scoping" \
      --kind code-context \
      --pattern "src/auth/**"
    ```
  </Step>
  <Step title="Let Driftless watch your code">
    Connect the GitHub App so topics automatically go stale when the files they cover change in PRs or pushes.
  </Step>
</Steps>

<Note>
  Your source code never leaves your machine. Driftless stores structural metadata and topic text only — not raw code or secrets.
</Note>
