---
title: 'Driftless'
description: 'Shared codebase memory for engineering teams and coding agents.'
---

Driftless keeps architectural context alive across sessions, repos, and contributors.

It is not a PR reviewer, CI gate, or cache. It is the durable context layer your team updates as the codebase changes, then loads before the next edit.

## Two ways to use Driftless

<CardGroup cols={2}>
  <Card title="Scan your code" icon="scan-search">
    Run `driftless init`. It scans your codebase (NestJS, Next.js, React), auto-generates topics from the AST, and anchors them to the files they describe. When code changes on tracked branches, topics go stale — you know what to review.
  </Card>
  <Card title="Write context manually" icon="pencil">
    Run `driftless context add`. Write topics by hand — what, how, decisions, gotchas. Link them with typed relations. Use `[[wiki-links]]` to cross-reference. Anchor documents with `--file`. Build a team knowledge graph that connects code to decisions.
  </Card>
</CardGroup>

Both paths converge: topics live in Cloud, agents and humans load them before editing, and the graph shows how everything connects.

## Quickstart

<Steps>
  <Step title="Install & login">
    ```bash
    npm install -g @driftless-sh/cli
    driftless login
    ```
  </Step>

  <Step title="Init (scan your code)">
    From any Git repo:

    ```bash
    driftless init
    ```

    Scans your code, uploads a baseline, auto-generates suggested topics, and installs the agent skill (AGENTS.md + CLAUDE.md).
  </Step>

  <Step title="Create a topic">
    Auto-generated from scan:

    ```bash
    # Topics appear after init — review and refine them
    driftless context list --auto
    ```

    Or write one by hand:

    ```bash
    driftless context add "auth-flow" \
      --what "JWT validation and role-based access control" \
      --how "RS256 asymmetric keys, guard decodes, role decorator checks" \
      --pattern "src/auth/**" \
      --tags auth,security
    ```
  </Step>

  <Step title="Load before editing">
    ```bash
    driftless context load --files "src/auth/guard.ts,src/users/service.ts"
    ```

    Returns matching topics, coverage status, and recommended actions.
  </Step>

  <Step title="Persist what you learn">
    ```bash
    driftless context update auth-flow \
      --decision "Chose RS256 over HS256 — services verify without shared secret" \
      --gotcha "Token refresh is NOT handled by this guard; see [[token-refresh]]"
    ```
  </Step>
</Steps>

## The loop

<Steps>
  <Step title="Sync">
    Pull team context changes before starting work.

    ```bash
    driftless sync
    ```
  </Step>

  <Step title="Load">
    Ask Cloud what applies to the files you are about to touch.

    ```bash
    driftless context load --files "src/auth/guard.ts,src/users/service.ts"
    ```
  </Step>

  <Step title="Persist">
    Append durable decisions, gotchas, and anchors after you learn something.

    ```bash
    driftless context update auth --gotcha "JWT decode happens in guard, not middleware"
    ```
  </Step>
</Steps>

## Boundaries

Driftless informs. It never modifies code, approves PRs, blocks merges, runs tests, or exposes an MCP server in v1.
