---
title: 'Drift and freshness'
description: 'How Brein flags a document whose anchored engineering paths may have changed.'
---

Drift is an engineering-context signal, not a commercial-market signal. It helps a software team notice when a document's anchored paths may no longer support the claim inside it.

## Local inspection

From a checkout:

```bash
driftless context get --diff
driftless context get --diff --mark
```

The first command displays matching documents without changing workspace state. `--mark` is explicit and records the drift signal for the matched documents. A match says "look again", not "the document is false".

## What to do next

1. Read the changed code or configuration.
2. Read the anchored document and decide whether the durable claim changed.
3. If it still holds, rewrite or refresh the document as needed.
4. If the anchor is no longer relevant, remove or narrow it.
5. If the document is no longer part of the workspace's current work, archive it through the human-owned lifecycle.

The current document model has no `status: reviewed` promotion that makes a document authoritative. Freshness comes from the current document and its anchor relationship, not from a retired governance badge.

## Optional diagnostics

```bash
driftless context doctor
driftless sync
```

`context doctor` audits the technical document layer. `sync` remains a compatibility digest for older repository workflows; it is not a customer briefing or a commercial automation. Brein's commercial intelligence has its own evidence and freshness semantics.

## Safety

Drift is a nudge, not an alarm. It tolerates false positives so a human can make the final decision. It never means that an agent should rewrite a document automatically, send a message, or create a CRM Record.
