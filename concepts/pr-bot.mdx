---
title: 'PR Bot'
description: 'Delivers the team’s recorded context to whoever reviews a PR.'
---

When a pull request touches a documented area, the Driftless PR bot posts one comment that **delivers the team's recorded context to the reviewer**. The reviewer sees the gotchas, decisions, and invariants the team wrote down for that area — so they review *with* the context instead of without it. It informs; it never blocks, and it does not score coverage.

## How it works

When a PR is opened or updated, the bot:

1. Fetches the list of changed files from GitHub.
2. Intersects each file path against every workspace topic's anchor patterns (globs).
3. Posts a single sticky comment with the matched topics' recorded context.

The matching is **glob-only** — each topic's `patterns` are matched against the PR file list. No language parser or code analysis is involved.

## What the comment delivers

For every topic whose patterns match a file in the PR, the comment surfaces what the team recorded:

```text
### auth-boundaries  ✓ authoritative
**Applies to:** src/auth/session.ts, src/auth/tenant.ts
**How:** 2 endpoints, 1 service, 1 guard
**Decisions:** Multi-tenant, uses org_id from token
**Gotchas:** All endpoints require auth; do not add @Public() without review
**Invariants:** Webhook handlers must be idempotent
```

If a matched topic is **stale** (its covered code changed since the context was written), the comment flags it so the reviewer knows the note may be behind. If it's still a `draft` (not yet approved), it's shown as a hint, not authority.

## It informs, never blocks

The PR bot is **context for the reviewer** — not a coverage score, not homework for the author. It does not count "uncovered" files, assign a percentage, or demand new topics. The way the context layer grows is the everyday loop (persist after a session, pull before editing), not a gate on the PR.

If your change altered how an area works, update the topic so the note stays true:

```bash
driftless context update auth-boundaries --gotcha "..." --decision "..."
# or open a topic-PR if it's already approved:
driftless context pr auth-boundaries --open --summary "..." --content @new.md
```

## Configuration

- The bot is active on any repo where the GitHub App is installed and the repo is linked to a workspace.
- The comment is updated in place on new commits — never re-posted.
- Only files changed in the PR are matched; the bot does not inspect the entire repo.

<Note>
The PR bot respects governance: it labels authoritative (`reviewed`) topics as truth and flags stale or draft ones. The reviewer always sees *which* context is blessed and *which* is just a hint.
</Note>
