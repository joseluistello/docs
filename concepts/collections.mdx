A **Collection** is a configured workspace table. A **Record** is one typed row. In the current Brein product, the customer-facing use is Prospectos: a Collection of people the workspace has explicitly acquired and filed.

A company, supplier observation, tender, award, permit, risk mark, or research row is not a CRM Record. Those objects can remain market context or evidence. A person becomes a Record only through the revealed/imported-contact path.

## What a Prospectos Collection holds

- **Contact fields:** the person, account, role, channel availability, and bounded sales fields the workspace needs.
- **Lifecycle:** named stages such as new, contacted, replied, meeting, closed, or discarded, configured for the team's sales process.
- **Cerebro criterion:** the documents that explain how the team should work these contacts.
- **Bounded reads:** active-only pages by default, with continuation when more records exist.

The underlying Collection/Record model is shared infrastructure. It is not a promise that Brein is a generic database builder for bug trackers, calendars, or arbitrary schemas.

## Contact-first lifecycle

```text
masked person candidate
  → explicit quote and confirmation
  → revealed/imported contact
  → explicit people_file
  → CRM Record
  → status, history, and follow-up
```

`crm_record` updates an existing contact Record. It does not create one from a company or evidence row. `collection_query` reads; `crm_collection` creates an empty container; `people_file` files the acquired person.

## MCP contract

The current MCP surface is:

- `collection_query` — bounded list, query, get, and aggregate reads;
- `crm_record` — update an existing contact Record, read history, or schedule follow-up;
- `crm_collection` — create an empty contact-oriented Collection;
- `people_file` — create the contact Record from a revealed/imported person.

Generic Collection schema CRUD, `entity`, permanent purge, and Record delete are not public MCP tools. The former `collection_record` name is a hidden compatibility alias for reads and existing-Record updates; it does not restore the old company/account creation behavior.

## CLI and REST

The CLI and REST still expose lower-level configuration and lifecycle operations for administrators and technical clients. Read the current command or endpoint contract before using them; do not infer a customer workflow from the existence of a generic Record route.

## Entities

Entities may exist as a shared identity model inside the platform, but the public MCP entity tool is not part of the commercial product. A person, company, or external observation is linked to CRM work only when the server can attest the relationship; approximate names and client URLs are not identity proof.
